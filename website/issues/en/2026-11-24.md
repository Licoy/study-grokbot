## What this issue covers {#intro}

Over 23 issues we've covered memory, connected apps, the cloud computer, Vault, approvals, skills, and routines. Each is simple on its own, but people often ask how they fit together: when I send one message, what does the Bot do first, and where does it stop and wait for me?

The official docs have a page that answers exactly this, following one everyday request from start to finish. This issue walks through that example, turns each step into a tip, and explains the security limits of a Bot that acts as you. Afterward, the earlier issues should make more sense, because you'll know where each feature sits in the flow.

::: callout The one thing to remember
The Bot checks memory first, uses apps next, and opens a browser only when there's no app. Logins never pass through its eyes, actions get checked before they go out, and everything it does is done as you.
:::

## One request, five steps {#flow}

The official example: you have a Bot for travel and expenses, and you send it "Sign me up for the same conference as last year and expense it." The message doesn't say which conference, which pass, or which card. The Bot works through it like this:

::: steps
- Check memory | It finds last year's pass in its work log, and the rule you gave it to use the work card for conferences.
- Use a connected app | It finds last year's receipt in Gmail.
- Sign in and buy | The conference site has no app, so it opens the site in a browser on its cloud computer, signs in with Vault or a Secure Form, and pays.
- Ask before sending | It's ready to email the receipt to finance, but you made a rule to approve emails first, so it stops and asks.
- Log and report | It adds the expense to your sheet in Google Drive and replies with everything it did.
:::

The five tips below follow the same order.

## Five tips you can use today {#tips}

Each tip comes with an example prompt. Replace the parts in square brackets with your own details and send it. Sign-in and payment steps must be done by you.

### Tip 1: Say lasting rules once and let memory keep them {#tip1}

The official docs say each Bot has its own memory with three kinds of things:

::: props
- Preferences: for example, "keep morning briefs short"
- Rules: how you want it to work every time, for example, "use the work card for conferences"
- Work log: a dated record, for example, which pass it bought last year and what it cost
:::

A few facts about you, like your name and time zone, are shared by all your Bots. Tell any Bot your time zone and all your Bots know it. Tell your expenses Bot where receipts go and only that Bot knows it.

A Bot decides on its own what to remember, and you can ask it to remember, fix, or forget something. The official docs warn that memories can go out of date, so ask the Bot to look up numbers that change, like prices or budgets. Keep logins and cards out of memory and in Vault. Lasting rules go to memory; the details of a single task go in your message. See [Issue 6](/issues/2026-11-06/) for keeping memory accurate.

::: prompt
Please remember this lasting rule: [the rule, for example, always book hotels with free cancellation for work trips].
It's only a rule; I'll give you the dates and budget in each message.
Once saved, repeat back the exact wording, and tell me whether it's in your own memory or shared by all my Bots.
:::

### Tip 2: Connect the services you use often as apps {#tip2}

In the example, the Bot found the receipt with the connected Gmail app instead of clicking through the website. The official docs say a connected app lets the Bot work in the service directly, which is more reliable than clicking through pages in a browser.

So connect an app for each service you use often. If an app isn't in the catalog, ask a Bot to connect the service's MCP server. If the service has an API but no MCP server, the official tinkabot can wrap the API in a plugin with an MCP server and skills, test it, and publish it only when you say so. See [Issue 4](/issues/2026-11-04/) for connected apps and [Issue 22](/issues/2026-11-22/) for your own tools.

::: prompt
I often need to [task] in [service name].
First tell me: is there a connected app for it? If not, is there an official MCP server?
List the ways to connect it and what I'd need to do for each. Don't connect anything yet.
:::

### Tip 3: Know the order a Bot looks for logins {#tip3}

For a site with no app, the Bot opens it in a browser on its cloud computer. When a page asks for a password, it looks for a login in this order:

::: steps
- Vault | Logins you saved for your Bots.
- 1Password | Logins you approve in 1Password.
- Secure Form | If neither has one, it asks you with a secure form, then fills the page directly.
:::

Whichever it uses, the login goes straight into the page and the Bot never sees it. If a task needs an API key, the Bot sends you a secure secret card, and the key stays out of the chat. For single sign-on, a passkey, or a CAPTCHA it can't solve, the Bot hands you the computer: choose **Open computer** on the request, then **Take control**. Finish that step and tell the Bot to continue. See [Issue 15](/issues/2026-11-15/) for Vault.

::: prompt
I often need you to sign in to [site name].
Tell me: do Vault or 1Password have a login for this site right now?
If not, next time you need to sign in, send me a Secure Form. Don't ask me to paste a password into chat.
:::

### Tip 4: Use Custom rules to decide which steps ask you {#tip4}

Before a Bot runs a command, uses an app, or acts on its computer, Auto Review checks the action. It's on by default, and most actions go ahead on their own. When one needs you, the Bot shows an approval card with the action and its details, then waits.

You can add your own rules too. Open **Settings → General**, and under **Bot**, open **Custom rules**. Describe an action in plain words, like "send an email," and choose **Ask first** or **Allow automatically**. An Ask first rule always stops a matching action. In the example, that's the rule that stopped the email to finance.

::: props
- Edit rule: shows on a card stopped by an Ask first rule, and opens your Custom rules
- Always allow: can show on other cards, and saves a rule so similar actions run on their own next time
:::

The official docs suggest adding specific Ask first rules for sending, publishing, and deleting. To approve every payment, don't save the card in Vault. See [Issue 5](/issues/2026-11-05/) for approvals.

::: prompt
I want to add a few Ask first rules in Custom rules.
Based on what you've done for me recently, list the actions that can't be undone once sent or deleted.
Write each one as a short plain sentence I can paste in. Only suggest; don't change any settings.
:::

### Tip 5: Start new work with your primary Bot, and give repeat work its own Bot {#tip5}

Most Bots work best with one clear job, like the expenses Bot in the example. Your primary Bot is different. It's marked with a star in the sidebar, it's your main point of contact, it checks in with you on its own, and it coordinates your other Bots. You could send the example request to your primary Bot, and it could pass the work to your expenses Bot.

The official advice: start new work with your primary Bot. When the same kind of request keeps coming back with its own sources, rules, or schedule, give it its own Bot, or ask your primary Bot to create one. A Bot with one job builds up memory for that job, so you only explain it once. To set up several Bots at once, start from the official dr eggbot, which asks you a few questions and then sets up the Bots for you, one job each. See [Issue 7](/issues/2026-11-07/) for working with several Bots.

::: prompt
Look back at the work I've given you over the past month.
Find the kinds of requests that keep coming back and have their own sources, rules, or schedule.
For each, tell me whether it deserves its own Bot and why. Only suggest; don't create anything.
:::

## Security: a Bot acts as you {#security}

The official docs stress that a Bot has no account or credentials of its own. Everything it does, it does as you, so it can't do anything you couldn't, and every action traces back to you. The one exception is a connector your team manages, which can use team or service-account credentials.

::: steps
- App sign-ins stay away from the Bot | They stay on the servers, and the Bot uses your apps without getting them.
- Vault stays hidden | Saved logins and cards fill into the page without the Bot seeing them.
- Bots aren't separated | All your Bots share one cloud computer, with its files and browser sign-ins. Once one Bot signs in to a site, your other Bots are signed in too, and they can all use the cards in Vault.
- Only your messages count | Hidden text on a page isn't an instruction from you. This lowers the risk but doesn't remove it.
:::

So treat anything on the computer as available to all your Bots. Sign out of services a Bot no longer needs, and delete sensitive files when the work is done. Enterprise teams can also set a network policy and inference hooks; see [Issue 20](/issues/2026-11-20/).

::: prompt
Please do a security clean-up check for me:
1. List the sites that are signed in on the cloud computer's browser right now.
2. List the files on the computer that look like they hold personal or sensitive information.
3. For each item, say which recent task used it and whether you suggest keeping or removing it.
Only list them. Wait for my go-ahead before signing out or deleting anything.
:::

## Example: a made-up freelancer renews a course in one sentence {#case}

A made-up scenario (not anyone's real setup): a freelancer has a Bot just for expenses. Around this time every year, they renew an online course and log the cost in their expenses sheet.

::: props
- In memory: last year it bought the annual membership, and the rule is "use the second card for learning costs"
- Connected apps: email and a spreadsheet
- Custom rule: "send an email" is set to Ask first
:::

### Highlight: one sentence in, two stops {#case-flow}

The Bot needs the person only twice: once to fill in a Secure Form, and once to approve on an approval card.

::: flow
- Owner | Sends one sentence, handles the form and the approval card | person
- Expenses Bot | Checks memory, finds the receipt, renews, logs the cost
- Course site | Sign-in and payment
---
- Owner → Expenses Bot: Renew that course like last year and log the cost in my expenses sheet
- Expenses Bot → Course site: Opens the renewal page; neither Vault nor 1Password has a login
- Expenses Bot → Owner: I need to sign in to the course site. Please fill in this Secure Form
- Owner → Expenses Bot: Done
- Expenses Bot → Course site: Picks the annual membership and pays with the second card
- Expenses Bot → Owner: Renewed. I'm ready to email the receipt to your expenses inbox. This matches your Ask first rule, so please approve
- Owner → Expenses Bot: Approved
:::

::: prompt
Do [task, for example renew a service] again, the same way as [last time].
Before you start, tell me which details you filled in from memory, which apps you plan to use, and which steps may need me to sign in or approve.
Start after I confirm, and list every step when you're done.
:::

## Community picks: making the whole flow work for you {#community}

Here are a few ways to get the most from this flow. The first four come from the official best practices; the last two build on the official docs and are offered for reference.

### Get it working once, then save a skill {#c1}

The official advice: get a task working once and save it as a skill. Then create a routine that runs it on a schedule or when something happens, like a Slack message or an email to your Bot. See [Issue 2](/issues/2026-11-02/) and [Issue 3](/issues/2026-11-03/) for routines and skills.

### Secrets never go in chat {#c2}

The official advice: passwords go through Vault, 1Password, or a Secure Form. Cards go through Vault or a Secure Form. API keys go through a secure secret card. Never paste a secret into a chat.

### One Bot per step in a group chat {#c3}

The official advice: in a group chat, make one Bot responsible for each step, so several Bots don't take on the same work.

### It keeps working while you're away {#c4}

The official docs say that if you close your laptop, the Bot keeps going and notifies you when it's done, and the chat shows each step it took. Once you hand off a long task, you don't need to watch the screen.

### Ask for the plan first {#c5}

For a complex request, ask the Bot to say which memories it will use, which apps it will open, and which steps need you to sign in or approve. Confirm, then let it start. It saves a lot of redo.

### Review what it remembers now and then {#c6}

Every so often, ask your Bot "which of my rules do you remember?" and fix the ones that are out of date. Accurate rules are what let a one-sentence request be filled in correctly.
