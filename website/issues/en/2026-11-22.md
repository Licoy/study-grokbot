## What this issue covers {#intro}

[Issue 4](/issues/2026-11-04/) covered the cloud computer and connected apps: services like Gmail, Notion, and Slack connect with a click from the catalog. Sooner or later, though, you need a service the catalog doesn't have, like a niche tool your team uses or a data platform that only offers an API.

The official docs give you three layers. Use an existing app first. If there isn't one, connect the service's MCP server. If there's no MCP server either, have tinkabot build a plugin from the API. This issue turns those layers into five tips, then covers the parts that trip people up: keys, permissions, and team policy.

::: callout The one thing to remember
Catalog first, MCP server second, your own plugin last. Keys go through secure cards only, and anything that writes gets an Ask first rule.
:::

## Five tips you can use today {#tips}

Each tip comes with an example prompt. Replace the parts in square brackets with your own details and send it. Sign-in and authorization steps must be done by you in your browser.

### Tip 1: Look for an existing app before you build anything {#tip1}

The official docs say apps give a Bot a structured way to work with a service, and when one exists it's more reliable than clicking through a website. Before you connect a custom tool, make sure the catalog really doesn't have it:

::: steps
- Open the catalog | Open Connect apps from the sidebar, search for the service, and add it.
- Sign in | When asked to Authorize or Authenticate, finish the provider's sign-in in your browser.
- Confirm it's installed | It's ready once it shows under Installed.
- Attach it to a task | Type @ in chat to attach the app to the current task.
:::

You can also ask a Bot to do it, for example "Add the Linear app." It searches the catalog, installs the app, and shows a Connect card if you need to sign in. The app's tools are ready from your next message.

::: prompt
I often use [service name] for [kind of work].
First, check the app catalog for this service:
1. If there's an app, tell me what it can do, then add it and give me a Connect card if I need to sign in.
2. If there isn't, tell me whether the service offers a public MCP server or an API.
Don't sign in to any website for me in the browser.
:::

### Tip 2: Let your Bot connect an MCP server {#tip2}

When the catalog doesn't have the service but the service offers an MCP server, hand it to your Bot. The official docs say a Bot can add an MCP server that isn't in the catalog in two ways:

::: props
- By URL: when the provider gives you a remote server address, give the address to your Bot
- By command: a command that runs on the Bot's computer starts the server; a server started this way is available to your other Bots too
- When it asks first: a server on a private network, or one that uses a private certificate authority, asks for your approval first
:::

::: prompt
Please connect the MCP server for [service name].
The provider's docs say to connect with: [paste the server address or the start command].
Before you connect, tell me:
1. Which tools it offers, and which ones only read and which ones change data.
2. Whether I need to sign in or provide a key.
3. Whether my other Bots will be able to use it.
Wait for my go-ahead before connecting.
:::

### Tip 3: Add a custom connector yourself in the desktop app {#tip3}

To do it yourself, open Connect apps in the desktop app, scroll to the bottom, and choose Add a custom connector. Enter a Name, then pick a Type:

| Type | What to fill in |
| --- | --- |
| Remote HTTPS | Server URL; optional HTTP headers and OAuth Client ID |
| Command | Command and Arguments |

A Client Secret field appears once you enter a Client ID. Choose Add plugin to save. If your team admin's MCP policy blocks the server, it can't be saved.

A custom connector you added yourself has no share link. To get a teammate set up, send them the provider's setup instructions and have them add it themselves.

::: prompt
I'm about to add [service name] with Add a custom connector in the desktop app.
Here are the provider's setup docs: [paste the docs].
Please work out:
1. Whether I should pick Remote HTTPS or Command.
2. What goes in each field. For secrets, write "I'll fill this in myself" and never the value.
3. How I can confirm it's connected afterward.
:::

### Tip 4: No MCP server? Have tinkabot build a plugin from the API {#tip4}

Plenty of services have an API but no MCP server. The official docs point to tinkabot in the Marketplace: it wraps the API in a plugin made of an MCP server and skills, tests it, and publishes it only when you say so.

According to its Marketplace listing, before publishing it asks once whether you work at the company or service. If yes, it publishes to the Cursor Marketplace; otherwise to cursor.directory. The listing also notes that Grok Bot loads plugins only from the Cursor dashboard and marketplace. Publishing means a public listing, so if the API belongs to an internal company system, check with your team first.

To import a Bot from the Marketplace, see [Issue 19](/issues/2026-11-19/).

::: prompt
@tinkabot I'd like to wrap the [service name] API in a plugin.
The API docs are here: [paste a link or the content].
The actions I use most are: [list two or three].
First tell me which tools you plan to offer and which keys you need, then report back once the tests pass.
Don't publish anywhere without my explicit go-ahead.
:::

### Tip 5: Keep keys and permissions under control {#tip5}

Custom tools need the same care as any other. These points from the official docs matter most:

::: steps
- Keys stay out of chat | When a task needs an API key, the Bot sends you a secure secret card. The key stays hidden and never appears in the chat.
- Tokens stay away from Bots | App sign-in tokens stay on Cursor's connector backend, and Bots use tools without receiving them.
- No extra access | An app can do only what the account you authorized can already do.
- Shared by all your Bots | A connected app is available to every Bot you run. A teammate's Team Bot asks before it uses your accounts.
- Ask before writing | Auto Review checks an action before a Bot uses an app. In Settings > General, under Bot, open Custom Rules and add Ask first rules for actions like deleting or publishing.
:::

For approvals and custom rules, see [Issue 5](/issues/2026-11-05/). For Vault and secure secrets, see [Issue 15](/issues/2026-11-15/).

::: prompt
I just added a custom connector for [service name].
List which of its tools change, delete, or publish data,
and draft a few Ask first rule descriptions for me, one sentence per kind of action.
Drafts only. I'll add them in Custom Rules myself.
:::

## Not connecting? Check the status first {#troubleshoot}

The official docs point out that Added means the app is installed, not that you're signed in. Check its status in Connect apps:

| Status or message | What to do |
| --- | --- |
| Needs auth or Disconnected | Choose Authenticate and sign in |
| Finish setting up | Add the server URL or other values, then connect |
| Disabled by team admin | Ask your team admin to turn it on |
| Connected, but still failing | Send the Bot a new message and ask it to retry |
| Client Secret keeps failing | Update the Client Secret in the connector settings, then reconnect |

If it still fails, or you revoked access on the provider's side, choose Remove, add it again, and sign in. Removing an app also removes everything it added and signs you out. For the general troubleshooting order, see [Issue 16](/issues/2026-11-16/).

::: prompt
My [service name] connection isn't working. Connect apps shows this status: [status text].
The Bot says: [paste the message].
Based on the official docs, tell me what to select next. If I need my team admin, write down exactly what to ask them. Steps only.
:::

## Limits to know when your team uses it {#limits}

::: steps
- Connector policy applies | Grok Bot inherits your team's Cursor connector policy. There's no separate Grok Bot connector list, and a blocked connector shows Disabled by team admin.
- The allowlist is Enterprise only | The MCP allowlist is an Enterprise feature, set on the Plugins & MCPs page of the dashboard.
- Network policy skips MCP by default | With an allowlist network policy, remote MCP servers are held to the same list only after an admin turns on Apply to MCP servers, which is off by default.
- Command servers are different | Servers run by a command on the computer already fall under the network policy, so the switch doesn't affect them.
- No pushing connectors | Admins can't push connectors to members as mandatory or default-on. Members add them in Connect apps.
:::

## Example: a made-up five-person design studio connects a niche board tool {#case}

A made-up scenario (not anyone's real setup): a five-person design studio tracks projects in a niche board tool. The catalog has no app for it, but the provider offers a remote MCP server with OAuth sign-in.

| Step | What they do |
| --- | --- |
| Check | Ask the primary Bot to search the catalog; no app |
| Read | Give the primary Bot the provider's setup docs |
| Add | Add it with Add a custom connector, Remote HTTPS |
| Sign in | Choose Authenticate and sign in in the browser |
| Rule | Add an Ask first rule for deleting cards |

### Highlight: the Bot prepares, a person authorizes {#case-flow}

The Bot only reads the docs, makes the checklist, and checks the result. Entering secrets and signing in stay with the person in charge.

::: flow
- Studio lead | Asks, then adds the connector | person
- Primary Bot | Checks the catalog and prepares the checklist
- Board tool | Offers tools over MCP
---
- Studio lead → Primary Bot: Is our board tool in the catalog? If not, look at these setup docs
- Primary Bot → Studio lead: It isn't. Pick Remote HTTPS. I've listed the URL and Client ID; please enter the Client Secret yourself
- Studio lead → Primary Bot: It's added and signed in. List this week's due cards. Read only, no changes
- Primary Bot → Studio lead: Here are this week's due cards. It also has a delete-card tool, so I suggest an Ask first rule
:::

::: prompt
From now on, when you work with [board tool name]:
1. Read only by default. Before creating, changing, or deleting cards, list the changes and wait for my OK.
2. Don't forward client details from the board to other apps.
3. If the connection drops, remind me to sign in again. Don't sign in through the browser instead.
Repeat these rules back to me first.
:::

## Community picks: getting the most from custom tools {#community}

Here are a few ways to work with custom tools. The first three come from the official best practices; the last two are extensions based on the official docs, for reference.

### Connect the services you use often {#c1}

The official advice: connect an app for each service you use often. If a service has no app, add its MCP server, or have tinkabot build one from its API. That's steadier than having the Bot click through the website every time.

### Secrets only through secure channels {#c2}

The official advice is never to paste a secret into a chat. Passwords go through Vault, 1Password, or a Secure Form, and API keys go through a secure secret card.

### Get it working, then save a skill {#c3}

The official advice is to get a task working once, save it as a skill, then create a routine that runs it on a schedule or when something happens. New tools are the same: use them by hand a few times before handing them to a routine.

### Read first, write later {#c4}

When a tool is new, have the Bot run only lookups at first. Once the data looks right, allow writes step by step, and add Ask first rules for deleting and publishing.

### Hand coding work to Cloud Agents {#c5}

If a tool needs code changes, the official docs say a Bot can hand coding work to Cursor Cloud Agents and attach the images, videos, and other files from the report to its reply. Team admins can turn this delegation off.
