## What this issue covers {#intro}

Tip 3 in Issue 1 noted that lasting rules belong in memory, and that memory is not an authoritative data source. Issue 5 added that memory writes sit outside Auto-review. This issue goes deep on what is remembered, how to change or remove it, and how facts are shared across Bots.

A Bot's memory is its long-lived context. It decides what is worth keeping; you can correct or forget things in chat. Used well, the Bot gets better with you. Left alone, stale facts quietly shape later answers.

::: callout The one thing to remember
Say "remember" for what matters; correct stale facts in place; put logins in Vault; re-check numbers at the source; don't rely on memory alone for safety boundaries.
:::

## Five tips you can use today {#tips}

Each tip comes with an example prompt. Replace the parts in brackets with your own and send it to your Bot.

### Tip 1: Tell memory from Vault {#tip1}

The official docs draw a clear line between what belongs in memory and what does not.

Memory typically keeps:

::: props
- How you work: Preferences and working style
- Rules: Lasting instructions, such as always ask before sending an email
- Facts about you: Name, time zone, and similar
- A work log: A dated summary of what you have done together
:::

These go in Vault, not memory:

::: props
- Logins: Account credentials
- Cards: Payment details
- Contact info: Addresses, phone numbers, and similar
:::

Vault is managed under Settings so a Bot can sign in or check out for you without writing passwords into ordinary memory. Dropping keys or addresses into chat as "please remember" is both unsafe and easy to mix up with real preferences.

::: prompt
Please confirm and remember these lasting preferences (do not store any password, card, or phone number):
1. My time zone is [time zone];
2. Always ask before sending any external email;
3. Default replies in [language/tone].
Then restate in three sentences what you kept. Logins and contact details go in Vault; do not put them in memory.
:::

### Tip 2: Say "remember" when it must stick {#tip2}

Your Bot decides on its own when something is worth keeping. It doesn't ask first. It often mentions a save in its reply, but not every save shows up in the chat. For rules that really matter, say it yourself.

The docs' example is plain: "Remember that I'm out every Friday."

What a Bot saves in one chat, it remembers in all your chats with it. Each Bot has its own memory. A few facts about you, such as your name and time zone, are shared by all your Bots—when one learns one of these, the others know it too.

In a voice chat, your Bot can draw on earlier calls and your recent chat with it. After you hang up, you can ask about the call in text chat. In a group chat, your Bot can use what you told it in private; each Bot keeps its own memory and doesn't share it with the other Bots there, but everyone in the group can read what your Bot says. Tell it if something should stay out of the group.

::: prompt
Please remember: [specific fact or rule].
This stays in effect for future related work.
After you save it, tell me whether this lives only in your own memory or in the small set of facts shared across all my Bots.
:::

### Tip 3: See, correct, or remove memory in chat {#tip3}

Personal Bots don't have a screen that lists their memory. Do it in chat:

::: props
- To see it: "What do you remember about me?"
- To correct it: "That's out of date. I moved to Denver."
- To remove it: "Forget that I'm on the launch team."
:::

When the Bot is still using a stale assumption, correcting it beats starting a new chat—resetting the conversation clears history, not memory.

If a fact that all your Bots share is wrong, tell any Bot the right version. To remove a shared fact completely, ask the Bot that saved it.

::: prompt
Please list the main things you currently remember about me and about your role, grouped by preference, rule, fact, and recent work.
Flag anything that may be out of date.
Then apply these updates now:
1. Correct: [old statement] → [new statement];
2. Forget: [fact that no longer holds].
Restate the updated points when you're done.
:::

### Tip 4: Know what Reset, Hide, and Delete do to memory {#tip4}

The official table:

| What you do | What happens to memory |
| --- | --- |
| Reset a conversation | Memory is kept |
| Delete a Bot | That Bot's memory is deleted (including shared facts it saved for your other Bots) |
| Delete your account | All your Bots' memory is deleted |

When a message is blocked, the notice can offer Reset. Choosing it starts the conversation history over; the Bot's memory, files, routines, and settings are kept.

Hide from sidebar keeps memory. Delete can't be undone: it erases conversations, memory, routines, and attachments, including the shared facts that Bot saved for your other Bots. If you may need the Bot later, hide it instead of deleting it.

A personal Bot's memory is yours. A shared Bot can save things for the whole team and tells you when it does; it doesn't save anything about you personally for the team. A teammate's shared Bot doesn't get the facts your own Bots share about you.

::: prompt
Please run a memory checkup (report only; don't delete yet):
1. Which memories are yours alone;
2. Which may be facts shared across all my Bots;
3. If I deleted you now, which shared facts might disappear with you.
Answer as a checklist.
:::

### Tip 5: Memory is not a source of truth {#tip5}

The docs call this out on its own: memory is not a substitute for an authoritative source.

::: steps
- Keep changing facts in the source system | Prices, stock, schedules, and similar stay at the source. For consequential decisions, ask the Bot to cite or reopen current data.
- Correct stale assumptions directly | If the Bot still uses an old address or title, say "That's out of date…".
- Back safety with rules | Approvals and Auto-review Custom Rules govern actions. Memory writes aren't covered by Auto-review, so "remember: ask before sending" is not a substitute for an Ask first rule.
- Import from another assistant | Under Settings → General → Import, choose Start Import. Copy the prompt into your other assistant, paste its answer into the second box, and choose Add to Memory. Grok Bot sends it to your primary Bot and opens that chat.
:::

Issue 5 covered this: Auto-review does not cover memory writes. "Remember not to send freely" and "Ask first before sending" are two layers—preference versus hard gate.

::: prompt
Please treat these as two different classes:
1. Lasting preferences that may go in memory: [list];
2. Data sources that must be re-checked every time: [system/sheet/page].
For class 2, reopen the source before any consequential conclusion; don't rely on old numbers in memory.
Also confirm: external sends, deletions, and payments still follow my approval rules, not a line in memory alone.
:::

## Limits you should know {#limits}

::: steps
- No memory list screen | Personal Bots manage memory in chat; there is no separate checklist page.
- Saves aren't always announced | The Bot often mentions a save, but not every save appears in the reply.
- Delete a Bot can't be undone | It clears that Bot's memory and the shared facts it saved for other Bots. Hide if you want to keep memory.
- Group chats see what is said | Memory isn't shared between Bots in the group, but everyone can read what your Bot says out loud.
- Memory writes skip Auto-review | Hard safety requirements belong in approval / Auto-review rules, not memory alone.
:::

## Case study: a memory cleanup for the newsletter team {#case}

Continuing the fictional lineup from earlier issues (not anyone's real setup): Research Bot, Writer Bot, Reviewer Bot, Planner Bot, and Builder Bot. After a few weeks, some still used an old deadline, and some had treated a one-off tone as a lasting rule. They ran a memory cleanup:

| Bot | Keep | Forget / correct | Not for memory |
| --- | --- | --- | --- |
| Research Bot | Cite publicly checkable sources; include links | Last week's temporary "internal docs only today" | Paid-library logins → Vault |
| Writer Bot | Newsletter tone and title length | Expired holiday-special tone | Publishing-channel logins → Vault |
| Reviewer Bot | Checklist: facts, links, sensitive terms | None | None |
| Planner Bot | Team time zone; ask before sending invites | Cancelled biweekly meeting | Room-door codes → Vault |
| Builder Bot | Test commands and branch naming | Retired deploy flow | Deploy keys → Vault / Secrets |

### Highlight: inventory, then correct, then check the gates {#case-flow}

They didn't delete Bots first. They followed see → correct → confirm rules → check approval rules.

::: flow
- Planner Bot | Asks each Bot to list main memories
- Each Bot | Corrects stale items, forgets temporary instructions
- Me | Confirms shared facts such as time zone | person
- Approval rules | Verifies Ask first rules still exist; memory is not a substitute
---
- Planner Bot → Each Bot: starts the inventory
- Each Bot → Me: returns the list and proposed fixes
- Me → Each Bot: approves corrections / deletions
- Me → Approval rules: confirms the hard gates remain
:::

If a shared time zone is wrong, tell any Bot the right version. To fully remove a shared fact that Writer Bot originally saved, tell Writer Bot to forget it.

::: prompt
You're this team's Planner Bot. Draft a memory-maintenance checklist for Research Bot, Writer Bot, Reviewer Bot, and Builder Bot:
1. Three lasting items each should keep;
2. Two items that may be stale and need my confirmation;
3. One class of info that must not go in memory and belongs in Vault.
Plan only; don't change any memory.
:::

## Community picks: common ways to tend memory {#community}

Here are a few common, easy-to-start ideas. They're general, so swap in your own details.

### Ask every Friday {#c1}

A fixed question—"What do you remember about me? Anything out of date?"—beats fixing mistakes after they land.

### Give temporary prefs an expiry {#c2}

When you state a short-lived preference, add a shelf life, such as "only this week; forget it next week." When it expires, tell the Bot to forget it.

### Three lines for a new Bot {#c3}

Right after create: who it is, lasting rules, and which facts must be re-checked at the source every time. Have it restate them before real work starts.

### Private secrets, public summaries {#c4}

Tell the Bot explicitly not to repeat anything that must stay out of group chats. When the group needs collaboration, share only a public-safe summary.

### Inventory right after Import {#c5}

After you Import from another assistant into your primary Bot, ask what it remembers, delete anything that shouldn't stay, then start normal use.
