## 本期导读 {#intro}

用了一阵 GrokBot 之后，很多人会发现：同一个 Bot，有时一次就做对，有时绕了一大圈还要返工。差别往往不在 Bot，而在于这件事交代得清不清楚。

官方文档里有一段专门讲怎么让对话更有效，另外几页也散落着相关的建议：怎么写第一个任务、怎么在请求里写边界、怎么中途改需求、怎么用线程和搜索。本期把它们串起来，整理成 5 个可以马上用上的习惯。审稿和代打电话这类跑腿场景见[第 23 期](/zh/issues/2026-11-23/)，快捷键全表见[第 17 期](/zh/issues/2026-11-17/)。

::: callout 一句话记住本期
先说要什么结果，再说能做到哪一步；让 Bot 拿证据说话，改主意就直接说，旧工作用搜索找回来。
:::

官方的说法是：使用 GrokBot 的感觉应该像给一位同事发消息。请求可以写得很自然，但要把结果和决策边界说清楚：Bot 可以改什么，在哪里必须停下来等你。

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接用。

### 技巧一：像交代同事一样提需求 {#tip1}

官方入门指南给第一个任务的建议是：像问同事那样问，说清四件事。

::: steps
- 要什么结果 | 最后交回来的是一份汇总、一个草稿，还是一张表格。
- 用哪些来源 | 收件箱、日历、某个文档，最好直接贴上权威来源的链接。
- 有什么限制 | 范围、时间段、格式，以及哪些事情不要做。
- 什么时候找你 | 遇到哪类情况要先停下来问你。
:::

官方还特别提醒：开头先写你需要的结果，不要把每一次点击都详细地模仿出来。步骤交给 Bot 去想，你只管把目标和边界说清楚。

发消息时，除了文字，你还可以粘贴链接和图片、附上本地文件、语音输入、按名字调用一个已保存的技能，或者用 `@` 提到某个 Bot、群组、Routine 或应用。

::: prompt
请帮我 [要的结果，例如：整理出本周客户反馈的前五个问题]。
来源只用 [来源链接或应用名称]，时间范围是 [时间段]。
做成 [格式，例如：一张五行的表格，每行附原始链接]。
遇到来源里缺数据或者互相矛盾的地方，先停下来问我。
:::

### 技巧二：在请求里写明边界 {#tip2}

审批卡片会在敏感动作前拦一下，但更稳的做法是在请求里就把边界写清楚。官方建议下面这些动作都要明确写边界：

::: props
- 对外沟通: 发送消息或邀请
- 公开发布: 发布任何内容
- 花钱: 购买和转账
- 数据: 删除或覆盖数据
- 权限: 修改权限
- 线上环境: 改动生产环境
- 法律: 接受法律条款
:::

官方示例的写法是：先说要做的工作，再说不许做什么，最后说什么时候、带着什么信息来找你批准。要记住，批准只管将要做的那个动作，撤不回已经做完的工作。

::: prompt
请核对 [数据，例如：上个月的广告投放数据]，起草一份预算调整建议。
不要改动任何投放设置，也不要给任何人发消息。
需要我批准时，先列出当前值、建议值和预计影响，再等我回复。
:::

### 技巧三：让 Bot 拿出证据 {#tip3}

官方建议向 Bot 要证据：链接、截图，或者一份简短的操作记录。这样你不用从头复查，也能很快判断它做得对不对。对话记录里本来就会显示工具调用、电脑操作、生成的文件、提问和审批请求，证据能帮你在这些记录里抓住重点。

还有一点容易被忽略：记忆不能代替权威来源。官方的建议是，经常变化的事实留在原来的系统里；做重要决定时，让 Bot 引用或者重新打开最新的数据；发现它记错了，直接纠正。长期有效的偏好要明确说出来，记忆的维护方法见[第 6 期](/zh/issues/2026-11-06/)。

::: prompt
做完之后，请附上：
1. 你用到的每个来源的链接；
2. 关键页面的截图；
3. 一份不超过十行的操作记录，写清楚你改了什么、没改什么。
涉及数字的结论，请重新打开最新数据核对，不要只凭记忆。
:::

### 技巧四：中途改向，用好线程和回应 {#tip4}

计划变了不用等 Bot 做完。官方说明：你直接发的新消息会优先于后台工作，可以改变当前这一轮。需要马上结束时，就直接发一句“现在停下”；不过已经做完的动作不会被撤销。

对话变长以后，用好这几个小工具：

::: steps
- 回复某一条 | 针对某个结果或某个审批请求的意见，在线程里回复，主对话不乱，决策的上下文也留得住。
- 表情回应 | 适合轻量的确认；需要改指令时写文字，涉及安全的决定不要只靠一个表情。
- 换线程或换 Bot | 对话已经变成另一件长期的工作时，开一个新线程，或者新建一个 Bot 专门负责。
:::

::: prompt
先暂停刚才的方向。新的优先级是 [新的要求]。
请告诉我：到现在为止你已经做完了哪些动作，哪些还没开始；
按新的要求，接下来你打算怎么做。等我确认再继续。
:::

### 技巧五：用搜索找回以前的工作 {#tip5}

找不到上周 Bot 做的文件或说过的话，不用翻聊天记录。在桌面端，搜索面板可以：

::: props
- 切换: 在 Bot 和群组之间切换
- 找消息: 跨对话找以前的消息
- 找成果: 找文件、链接和 Routine
- 找设置: 打开设置和常用操作
- 跳回原处: 回到对话里对应的位置
:::

按 `Cmd/Ctrl+K` 打开搜索面板，按 `Cmd/Ctrl+Shift+F` 搜索 Bot，按 `Cmd/Ctrl+F` 在当前对话里查找。结果显示 **Searched recent messages** 时，选 **Search older** 继续往前找。选中一段文字后按 `Cmd/Ctrl+L`，可以把它加进对话里接着追问。

::: prompt
上周你帮我做过一份 [成果名称，例如：竞品价格对比]。
请找出那份文件和当时的对话，告诉我它用的数据截止到哪天，
再按最新数据更新一版，把改动的地方列出来。
:::

## 几个必须知道的边界 {#limits}

::: props
- 停下不等于撤销: “现在停下”只会结束接下来的工作，已经做完的动作不会撤回
- 批准不等于撤销: 批准只管将要做的动作，不会撤回已经完成的工作
- 表情不是指令: 表情回应只适合轻量确认，涉及安全的决定要写文字
- 记忆不是来源: 重要的事实以原系统为准，安全边界要靠审批和自动审查规则，不能只靠记忆
- Bot 会主动，但先问: 你的主 Bot 会主动提出帮你做事，但它会先问你，做有风险的动作前也会先请你确认
:::

## 实战案例：虚构的一位活动策划，把一句话需求改成一次做对 {#case}

一个虚构的场景（并非任何人的真实配置）：一位活动策划让 Bot 帮忙准备下个月的线下分享会。她一开始只发了一句“帮我准备一下分享会”，结果 Bot 问了好几轮才弄清楚要什么。

::: props
- 起点: 一句话需求，没有来源，没有边界
- 目标: 一次交代清楚，拿回一份能直接用的筹备清单
- 顾虑: 不希望 Bot 擅自给嘉宾发邀请
:::

### 亮点：四要素、写边界、要证据、改方向 {#case-flow}

::: steps
- 重写需求 | 按技巧一写清结果（一份筹备清单）、来源（场地报价文档的链接）、限制（预算上限、日期）和什么时候找她。
- 写明边界 | 照技巧二加一句：邀请只起草，不发送，发送前先给她看名单和正文。
- 要证据 | 让 Bot 每个场地都附上报价来源的链接，结论末尾附一份简短的操作记录。
- 中途改向 | 做到一半，日期改了，她直接发新消息说明新日期，Bot 先汇报已经做完的部分，再按新日期调整。
:::

::: prompt
我在准备 [活动名称]。请交回一份筹备清单：场地、物料、嘉宾邀请三个部分。
来源只用 [文档链接]，预算上限 [金额]，日期 [日期]。
邀请只起草，不要发送；发送前先把名单和正文给我看。
每个场地附上报价来源的链接，最后附一份简短的操作记录。
:::

## 社区玩法精选：和 Bot 沟通的小习惯 {#community}

本期整理了几种和 Bot 沟通的做法：前三条出自官方文档的说明和建议，后三条是基于官方文档的延伸用法，供你参考。

### 一件长期工作一个线程 {#c1}

官方建议：对话已经变成另一件长期的工作时，开一个新线程，或者新建一个 Bot。一个对话只管一件事，Bot 不容易把上下文搞混。

### 语音说完再改再发 {#c2}

桌面端在输入框里按 `Cmd/Ctrl+D` 可以语音输入，说出来的话先变成文字，你看过、改好再发。想到哪说到哪的需求，用这个方式最快。

### 用 @ 把东西点名 {#c3}

在消息里用 `@` 提到某个 Bot、群组、Routine 或应用，比用文字描述“那个每天早上跑的任务”更准确。

### 固定一段“结尾三句” {#c4}

在常用的提示词末尾固定加上三句：附上来源链接、附上操作记录、哪些事不要做。习惯成自然，每次都少返工。

### 先让 Bot 复述一遍 {#c5}

复杂的任务，先让 Bot 用几句话复述它理解的目标和边界，确认无误再开工。复述错了，改一句话就行，比做完再返工省得多。

### 纠正时说“以后都这样” {#c6}

Bot 做法不对时，除了指出这一次的问题，再明确说一句以后都按这个来。官方建议长期偏好要明确纠正，这样下次不用再说一遍。

## 本期小练习 {#exercise}

花 15 分钟，把一个常用需求改写得更清楚。

::: steps
- 改写需求 | 挑一个你常发给 Bot 的需求，用技巧一的四要素重写一遍。
- 加上边界 | 照技巧二，写清楚它不能做什么、什么时候来找你。
- 要证据 | 用技巧三的提示词，让它这次附上来源链接和操作记录。
- 找回旧工作 | 按 Cmd/Ctrl+K，找出 Bot 上周做过的一份文件。
:::
