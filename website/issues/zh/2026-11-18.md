## 本期导读 {#intro}

前面十几期，我们把 GrokBot 的功能一项项拆开讲过了：技能、Routine、云端电脑、审批、记忆、多 Bot 协作……但很多读者反馈，功能都懂了，打开聊天框还是不知道该让 Bot 先干点什么。

官方文档里有一页专门讲使用场景（Use cases），给出了一条很清楚的上手路线：先让 Bot 当助手，再把重复的事交给专职 Bot，最后组成 Bot 团队。本期就按这三步整理成 5 条技巧，每条都附了可以直接改着用的提示词。

::: callout 一句话记住本期
先连应用让 Bot 当助手，重复的事交给只干一件事的 Bot，大目标交给 Bot 团队；每一步都停下来等你审核，发送、发布和付款留在审批之后。
:::

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接用。

### 技巧一：先连上常用应用，让 Bot 当你的助手 {#tip1}

第一步是连上你已经在用的邮箱、日历、聊天工具和文档。连上之后，你的每个 Bot 都能读取并在里面干活；没有对应应用的服务，Bot 会用云端电脑上的浏览器去操作。连接方法见[第 4 期](/zh/issues/2026-11-04/)。

官方举了几个连上应用后就能做的例子：

::: props
- Google Drive: 读一个文件夹里的简报和往期材料，按你的格式起草下一份，放回 Drive 等你修改
- Google Calendar: 每周日晚上看一遍下周日程，标出冲突和排得太满的日子，给你一份周一的简短安排
- Gmail: 在你起床前把夜里的邮件分好类，给需要你回复的邮件起草回信，所有草稿都留给你来发
- Granola: 每天傍晚读当天的会议笔记，列出每条待办和负责人，起草一条团队频道的消息，你批准后才发出
- Slack: 留意有人提到你的消息，先动手做对方要的东西，比如一段文案，把草稿交给你批准后再回复
- Notion: 每周五给每个项目页面起草进展更新，标出变化，你批准后再加进去
:::

除了这些，平时要自己去查的事也可以直接问 Bot：昨晚有什么变化、下一个会议有谁参加、竞争对手这周发布了什么。它会跨你连上的应用去读，并把下一步起草好。

::: prompt
帮我做一份今天的早间简报：
1. 汇总从昨天到现在，我的邮箱、日历、[聊天工具] 和文档里有哪些变化；
2. 单独列出需要我亲自处理的事项；
3. 整理成一条可以发到 [团队频道] 的消息草稿，先不要发送。
:::

### 技巧二：从五个现成的助手场景开始 {#tip2}

官方给助手阶段准备了五个场景，每个都附了起步提示词。它们的共同点是：结果先交给你看，Bot 不替你发送、预订或购买。

| 场景 | 你会得到什么 |
| --- | --- |
| 早间简报 | 一份“哪些事需要你”的晨间汇总，可以直接发出 |
| 收件箱整理 | 紧急邮件排在最前，回信已经起草好，等你确认 |
| 竞品动态 | 竞争对手本周的新品或调价，附链接 |
| 出行比价 | 两个最合适的航班和酒店方案，由你来选 |
| 会前准备 | 一页纸简报：参会人、上次聊到哪里、还有哪些悬而未决的事 |

把官方的提示词改成你自己的，关键是保留结尾那句“不要发送”或“不要预订”。

::: prompt
帮我准备 [今天下午两点] 的会议：
1. 谁会参加，我和他们上次聊的是什么；
2. 还有哪些没有结论的事项；
3. 控制在一页以内。
只整理资料，不要替我给任何人发消息。
:::

### 技巧三：把每周都要说一遍的事，交给专职 Bot {#tip3}

留意那些你每周都要提一次的请求，比如筛选新线索、核对发票。把每一件交给一个只干这件事的 Bot，它会为这件事积累上下文，越做越顺。

新的工作先交给主 Bot（侧边栏里带星标的那个）。当同一类请求反复出现，并且有自己的资料来源、规则、时间安排或审批要求时，再单独给它一个 Bot，或者请主 Bot 帮你建一个。

官方列出的专职 Bot 例子覆盖了不少岗位：

| 专职 Bot | 它负责什么 |
| --- | --- |
| 销售拓展 | 按理想客户画像筛选当天的新线索，给合适的起草介绍信，给不合适的起草婉拒 |
| 发票核对 | 把财务邮箱里的发票和采购单对上，列出对不上的，起草给负责人的说明 |
| 内容营销 | 从更新日志和聊天记录里整理本周发布的内容，按你们的语气起草通讯和帖子 |
| 人才搜寻 | 按硬性条件找候选人，起草你口吻的联系信 |
| 费用管理 | 汇总本周报销，匹配收据，标出违反政策的条目 |
| 问题复现 | 用新的测试账号在测试环境里复现问题，给出步骤、截图和浏览器信息 |
| 客户健康度 | 按用量、工单和续约时间给客户排序，标出流失风险和扩展机会 |

这些例子都停在“起草”和“建议”这一步：不联系任何人、不批准付款、不改预算、不动生产环境。

::: prompt
我想新建一个专职 Bot，帮我做一个计划：
1. 它只负责 [一件事，比如每周核对报销收据]；
2. 它需要连哪些应用、读哪些资料；
3. 哪些动作必须先问我，比如发送、付款和删除；
先给我方案，等我确认后再创建。
:::

### 技巧四：跑通一次，再让专职 Bot 自己运行 {#tip4}

当专职 Bot 已经能按你想要的方式完成工作，就可以让它自己跑起来。官方建议按下面三步来：

::: steps
- 讲清职责并让它记住 | 在聊天里告诉 Bot 它的职责和边界，并让它记住。长期有效的规则交给记忆，单次任务的细节写在消息里。
- 存成技能，再建 Routine | 把跑通的步骤存成技能，然后用 Routine 按时间表运行；Routine 也可以在收到某条聊天消息或发给 Bot 的邮件时触发。
- 账号走安全通道 | 测试账号保存在 Vault，或者用安全表单填写，绝不贴进聊天。
:::

还有一点容易忽略：价格、预算这类会变的数字，让 Bot 每次重新去查，不要依赖它记住的旧数字。

::: prompt
刚才这次 [费用汇总] 做得不错，我们把它固定下来：
1. 把你的职责和边界整理成几条规则，让我确认后记住；
2. 把这次的步骤存成一个技能；
3. 建一个 Routine，[每周五下午] 运行，结果发给我审核；
所有涉及金额的数字，每次都重新查，不要用记忆里的旧数字。
:::

### 技巧五：大目标交给 Bot 团队 {#tip5}

有些目标需要不止一份工作，比如一次产品发布宣传，或者月底结账。可以请主 Bot 搭几个 Bot，每个负责其中一段，它们把工作依次传下去，最后由你检查结果。不知道怎么拆分，可以从官方市场里的 [dr eggbot](https://x.ai/bot/marketplace/bots/dr-eggbot-v2) 开始：它会问你几个问题，再按“一个 Bot 一件事”帮你建好。

官方给了三个团队示例：

| 团队 | 分工 | 运行时间 |
| --- | --- | --- |
| 宣传团队 | 拉取上周各渠道的注册数据，据此起草发布说明和三条帖子，再对照数据和品牌文档核对一遍 | 每周一上午 9 点 |
| 月底结账 | 把发票和采购单对上，核对报销和收据，列出所有不一致等你签字 | 每月 1 日 |
| 客服队列 | 给新工单分类并起草回复，在测试环境复现问题，标出需要修改的帮助文档 | 工作日上午 9 点 |

在群聊里协作时，让每一步只由一个 Bot 负责，分工更清楚。多 Bot 协作和交接的细节见[第 7 期](/zh/issues/2026-11-07/)。

::: prompt
我想搭一个 Bot 团队来完成 [一个目标，比如每月的读者来信整理]：
1. 帮我把它拆成三到四步，每一步由一个 Bot 负责；
2. 说明每个 Bot 读什么、产出什么、交给谁；
3. 建议运行时间，以及哪些环节必须等我批准；
先给我方案，不要马上创建任何 Bot。
:::

## 几个必须知道的边界 {#limits}

::: steps
- 每一步都停下来等你 | 官方的所有示例都停在你审核这一步；发送、发布、购买和改动生产环境，一律放在审批之后。
- 用 Ask first 兜底 | 在 **Settings → General → Bot** 的 **Custom Rules** 里，给发送、发布和删除加上 **Ask first** 规则；想每次付款都由你批准，就不要把卡保存在 Vault 里。
- 电脑是共用的 | 你的所有 Bot 共用一台云端电脑，上面的文件和浏览器登录状态，其他 Bot 也能用。
- 密钥不进聊天 | 密码走 Vault、1Password 或安全表单，银行卡走 Vault 或安全表单，API 密钥走安全密钥卡片。
- 团队 Bot 不能当主 Bot | 主 Bot 是你的主要联系人，会主动找你、协调其他 Bot；团队 Bot 不能被设为主 Bot。
:::

## 实战案例：虚构的手作网店，从一个助手到一支小团队 {#case}

一个虚构的场景（并非任何人的真实配置）：一位手作网店的店主，起初只是让主 Bot 每天早上整理客户邮件。几周后，他发现自己每周都在重复同样的请求，于是一步步把工作交了出去。

| 阶段 | 做法 | 注意点 |
| --- | --- | --- |
| 助手 | 主 Bot 每天早上把客户邮件分成紧急、待回复和仅供参考，并起草回信 | 只起草，回信由店主自己发 |
| 专职 Bot | 新建“售后助手”，只负责退换货邮件 | 让它记住退换货规则，不碰其他邮件 |
| 自动运行 | 把处理步骤存成技能，用 Routine 每天上午运行 | 退款这一步加了 Ask first 规则 |
| 团队 | 再加“库存助手”和“周报助手”，由主 Bot 协调 | 群聊里每一步只由一个 Bot 负责 |

### 亮点：每一步都只交出去一点，出错也好收拾 {#case-flow}

店主没有一开始就搭团队，而是先确认每个 Bot 单独做得对，再把它们串起来。

::: flow
- 我 | 说明本周想交出去的工作 | person
- 主 Bot | 拆分任务并分派
- 售后助手 | 起草退换货回复
- 我 | 审核并批准退款 | person
---
- 我 → 主 Bot：以后退换货的邮件别再给我了，帮我建一个专门处理的 Bot
- 主 Bot → 我：已经起草了售后助手的职责和规则，你确认后我就创建
- 售后助手 → 我：今天有三封退换货邮件，回复都起草好了，其中一笔退款等你批准
- 我 → 售后助手：前两封没问题，退款那笔先等我和客户确认一下
:::

后来，店主让周报助手每周日晚上汇总一周的售后和库存情况，他只需要看一页纸。

::: prompt
你是这个“售后助手”。以后请按下面规则：
1. 只处理退换货相关的邮件，其他邮件交给主 Bot；
2. 回复只起草不发送，退款一律先等我批准；
3. 每天上午处理完后，告诉我有几封邮件、哪些需要我处理。
先复述规则。
:::

## 社区玩法精选 {#community}

本期整理了几类常见、好上手的用法，供大家参考。都是通用思路，具体内容换成你自己的。

### 提示词结尾写明不要发送 {#c1}

给 Bot 的任务最后加一句“只起草，不要发送”或“不要预订”，先看结果，再决定要不要放手。

### 一件事一个 Bot {#c2}

发现自己每周都在重复同一个请求，就把它交给一个专职 Bot，让它为这件事积累记忆。

### 先跑通，再存技能 {#c3}

手动和 Bot 一起把任务做对一次，再存成技能、建 Routine，比一开始就写一大段规则更可靠。

### 没有应用就请 Bot 补上 {#c4}

常用的服务没有现成的应用，可以让 Bot 接入它的 MCP 服务器；只有 API 的服务，可以试试官方市场里的 [tinkabot](https://x.ai/bot/marketplace/bots/tinkabot)，它会测试好、等你同意才发布。

### 团队先画分工表 {#c5}

搭 Bot 团队前，先让主 Bot 列一张表：每个 Bot 读什么、产出什么、交给谁，确认后再创建。
