## 本期导读 {#intro}

前面 23 期分别讲了记忆、连接应用、云端电脑、Vault、审批、技能和 Routine。每块单看都不难，可放在一起，常有人问：我发一句话，Bot 到底先做什么、后做什么？哪一步会停下来等我？

官方文档里有一页专门回答这个问题，用一个很日常的请求从头讲到尾。这一期就跟着这个例子把整个流程串起来，每一步对应一条技巧，再讲清 Bot 以你的身份做事时的安全边界。看完这一期，回头再看前面各期，会更清楚每个功能处在流程的哪个位置。

::: callout 一句话记住本期
Bot 先查记忆，再用应用，没有应用才开浏览器；登录不经它的眼，发出去之前过一道审查；它做的每件事都算在你的名下。
:::

## 一个请求，五个步骤 {#flow}

官方文档的例子是：你有一个管差旅和报销的 Bot，给它发了一句“帮我报名和去年一样的会议，再把费用报销掉”。这句话没说是哪个会议、买哪种票、用哪张卡，Bot 这样一步步做完：

::: steps
- 查记忆 | 从记忆里找到去年买的票种，以及你定过的“开会用工作卡”这条规则。
- 用连接应用 | 在 Gmail 里找到去年的收据。
- 登录并购票 | 会议网站没有应用，就用云端电脑上的浏览器打开，借助 Vault 或 Secure Form 登录，再付款。
- 发出前先问你 | 要把收据发给财务时，你定过“发邮件先问我”的规则，它就停下来等你批准。
- 记账并汇报 | 在 Google Drive 的表格里记下这笔费用，再回复你它做过的每一步。
:::

下面 5 条技巧，就按这个顺序展开。

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接用。涉及登录和付款的步骤，要由你本人完成。

### 技巧一：长期规则说一次，交给记忆 {#tip1}

官方文档说明，每个 Bot 有自己的记忆，存三类东西：

::: props
- 偏好: 例如“早报写短一点”
- 规则: 你要它长期遵守的做法，例如“开会用工作卡”
- 工作记录: 带日期的记录，例如去年买过哪种票、花了多少钱
:::

另外，你的名字和时区这类少数信息由你的所有 Bot 共享。所以对任何一个 Bot 说一次时区，所有 Bot 都知道；只告诉报销 Bot 收据该放哪，就只有它知道。

Bot 会自己决定记什么，你也可以请它记住、改正或忘掉某件事。官方提醒：记忆可能过时，价格、预算这类会变的数字，要请它重新查；登录信息和银行卡别放进记忆，放进 Vault。长期规则交给记忆，单次任务的细节写在当次消息里。记忆的维护方法见[第 6 期](/zh/issues/2026-11-06/)。

::: prompt
请记住这条长期规则：[规则内容，例如出差订酒店一律选可免费取消的]。
这只是规则，具体每次的日期和预算我会在消息里说。
记好后复述一遍你记下的原话，并告诉我它是存在你自己的记忆里，还是所有 Bot 共享。
:::

### 技巧二：常用的服务先连成应用 {#tip2}

在例子里，Bot 找收据时直接用了连接好的 Gmail，而不是打开网页去点。官方文档说明，连接应用让 Bot 直接在服务里操作，比在浏览器里一页页点更可靠。

所以，经常用的服务，就给它连一个应用。目录里没有的，可以请 Bot 接入该服务的 MCP 服务器；服务只有接口、没有 MCP 服务器的，官方的 tinkabot 可以把接口包成一个带 MCP 服务器和技能的插件，测试好，等你同意才发布。连接应用见[第 4 期](/zh/issues/2026-11-04/)，自建工具见[第 22 期](/zh/issues/2026-11-22/)。

::: prompt
我经常要在 [服务名称] 上 [做什么事]。
先告诉我：它有没有现成的连接应用？没有的话，有没有官方的 MCP 服务器？
请列出可行的接入方式和各自需要我做的步骤，先不要动手连接。
:::

### 技巧三：看懂登录的先后顺序 {#tip3}

没有应用的网站，Bot 会在云端电脑的浏览器里打开。遇到要密码的页面，它按这个顺序找登录信息：

::: steps
- Vault | 你为 Bot 存下的登录信息。
- 1Password | 你在 1Password 里批准使用的登录信息。
- Secure Form | 前两处都没有，就发一张安全表单问你，再直接填进网页。
:::

不管用的是哪一种，登录信息都直接进网页，Bot 本身看不到。需要 API 密钥时，它会发一张安全密钥卡，密钥不会出现在聊天里。至于单点登录、通行密钥、它解不开的验证码，Bot 会把电脑交给你：在请求上选 **Open computer**，再选 **Take control**，做完这一步告诉它继续。Vault 的用法见[第 15 期](/zh/issues/2026-11-15/)。

::: prompt
我经常需要你登录 [网站名称]。
请告诉我：现在 Vault 和 1Password 里有没有这个网站的登录信息？
没有的话，下次需要登录时请发 Secure Form 给我，不要让我把密码发在聊天里。
:::

### 技巧四：用 Custom rules 决定哪一步要问你 {#tip4}

Bot 执行命令、使用应用或在电脑上操作之前，自动审查（Auto Review）会先检查这个动作。它默认开启，大多数操作直接放行；需要你的时候，Bot 会发一张审批卡，写明动作和细节，然后等你。

你也可以自己加规则：打开 **Settings → General**，在 **Bot** 下打开 **Custom rules**，用大白话描述一个动作，比如“发送邮件”，再选 **Ask first** 或 **Allow automatically**。Ask first 规则一定会拦下匹配的动作，例子里拦住给财务发邮件的就是它。

::: props
- Edit rule: 被 Ask first 规则拦下的卡片上会有，点了打开你的 Custom rules
- Always allow: 其他卡片上可能出现，点了会存一条规则，以后同类动作自动放行
:::

官方建议给发送、发布和删除各加一条具体的 Ask first 规则；想每笔付款都自己批，就别把卡存进 Vault。审批的细节见[第 5 期](/zh/issues/2026-11-05/)。

::: prompt
我准备在 Custom rules 里加几条 Ask first 规则。
请根据你最近替我做过的事，列出哪些动作发出去或删掉后无法撤回，
每条用一句大白话写好，方便我直接填进去。只列建议，不要改任何设置。
:::

### 技巧五：新活先找主 Bot，重复的活交给专职 Bot {#tip5}

大多数 Bot 最适合只干一件明确的事，比如例子里的报销 Bot。主 Bot 不一样，它在侧边栏里标着星号，是你的主要联系人，会主动找你，也会协调你的其他 Bot。例子里的请求，你也可以发给主 Bot，由它转给报销 Bot。

官方的建议是：新的活先找主 Bot；同一类请求反复出现，又有自己的资料来源、规则或时间表，就给它单独建一个 Bot，或者请主 Bot 帮你建。专职 Bot 会为这件事积累记忆，你只需讲一次。想一次建好几个 Bot，可以从官方的 dr eggbot 开始，它会问你几个问题，再按一个 Bot 一件事帮你建好。多 Bot 协作见[第 7 期](/zh/issues/2026-11-07/)。

::: prompt
回顾一下最近一个月我交给你的活，
找出反复出现、而且有自己资料来源、规则或固定时间的那几类。
每类建议是否值得单独建一个 Bot，并说明理由。先给建议，不要新建。
:::

## 安全边界：Bot 以你的身份做事 {#security}

官方文档特别强调：Bot 没有自己的账号或凭据，它做的每件事都以你的身份进行，所以它做不了你本人做不了的事，每个动作都能追溯到你。唯一的例外是团队管理的连接器，它可以用团队或服务账号的凭据。

::: steps
- 应用登录不给 Bot | 应用的登录凭据保存在服务端，Bot 用应用时拿不到。
- Vault 不给 Bot 看 | 存下的登录和卡片直接填进网页，Bot 看不到。
- Bot 之间不隔离 | 所有 Bot 共用一台云端电脑，共享文件和浏览器登录；一个 Bot 登录过的网站，其他 Bot 也处于登录状态，也都能用 Vault 里的卡。
- 只认你的消息 | 只有你发的消息算指令，网页里藏的文字不算；但这只能降低风险，不能消除风险。
:::

所以，电脑上的东西要当成所有 Bot 都能用；某个 Bot 不再需要的服务就退出登录，敏感文件用完就删。企业团队还可以设网络策略和推理钩子，见[第 20 期](/zh/issues/2026-11-20/)。

::: prompt
请帮我做一次安全清理检查：
1. 列出云端电脑浏览器里目前登录着的网站；
2. 列出电脑上看起来含有个人或敏感信息的文件；
3. 每一项写明最近是哪个任务用到的、建议保留还是清理。
只列清单，退出登录和删除文件都等我确认。
:::

## 实战案例：虚构的一位自由职业者，一句话续订课程 {#case}

一个虚构的场景（并非任何人的真实配置）：一位自由职业者有一个专门管开支的 Bot。每年这时候，他都要续订一门线上课程，再把费用记进开支表。

::: props
- 记忆里有: 去年买的是年度会员，规则是“学习类开支用副卡”
- 连接的应用: 邮箱和表格
- 自定义规则: “发送邮件”设为 Ask first
:::

### 亮点：一句话进去，只停一次 {#case-flow}

整个过程里，Bot 只在登录和发邮件这两处需要本人：一次填 Secure Form，一次在审批卡上点批准。

::: flow
- 本人 | 发一句话，处理表单和审批卡 | person
- 开支 Bot | 查记忆、找收据、续订、记账
- 课程网站 | 登录和付款
---
- 本人 → 开支 Bot：照去年那样续订那门课，再把费用记到开支表
- 开支 Bot → 课程网站：打开续订页面，Vault 和 1Password 里都没有登录信息
- 开支 Bot → 本人：需要登录课程网站，请填写这张 Secure Form
- 本人 → 开支 Bot：已填好
- 开支 Bot → 课程网站：选年度会员，用副卡付款
- 开支 Bot → 本人：已续订。准备把收据发到我的报销邮箱，这一步命中你的 Ask first 规则，请批准
- 本人 → 开支 Bot：批准
:::

::: prompt
照 [上次的时间] 那样，再做一次 [任务，例如续订某项服务]。
开始前先告诉我：你从记忆里补全了哪些细节、打算用哪些应用、哪一步可能需要我登录或批准。
我确认后再开始，做完把每一步列给我。
:::

## 社区玩法精选：用好整个流程 {#community}

本期整理了几种用好这套流程的做法：前四条出自官方文档的最佳实践，后两条是基于官方文档的延伸用法，供你参考。

### 先让一个任务跑通，再存成技能 {#c1}

官方建议：先把一个任务做成功一次，再存成技能；然后建一个 Routine，按时间表运行，或者在某件事发生时运行，比如收到一条 Slack 消息或一封发给 Bot 的邮件。技能和 Routine 见[第 2 期](/zh/issues/2026-11-02/)和[第 3 期](/zh/issues/2026-11-03/)。

### 秘密永远不进聊天 {#c2}

官方建议：密码走 Vault、1Password 或 Secure Form，银行卡走 Vault 或 Secure Form，API 密钥走安全密钥卡，一律不贴进聊天。

### 群聊里每一步只交给一个 Bot {#c3}

官方建议：在群聊里，每一步指定一个负责的 Bot，避免几个 Bot 抢着做同一件事。

### 你不在时它照样干活 {#c4}

官方文档说明，你合上电脑后 Bot 会继续做，做完通知你；对话里会显示它做的每一步。长任务交出去之后，不用守着屏幕。

### 开工前先让它讲计划 {#c5}

复杂的请求，先让 Bot 说清它会查哪些记忆、用哪些应用、哪一步要你登录或批准，确认无误再开工，返工会少很多。

### 定期回看它记了什么 {#c6}

隔一段时间问一次 Bot“你记住了我哪些规则”，把过时的改掉。规则准了，一句话的请求才能被正确补全。
