## 本期导读 {#intro}

前几期讲的都是「你自己和自己的 Bot」。本期换个角度：想把一个调好的 Bot 给别人用，该怎么做？官方文档里有两种完全不同的分享方式，名字很像，作用却差别很大，混用最容易出事。

一种是**模板**：发一个链接，对方得到属于自己的副本。另一种是**共享 Bot**：把 Bot 本身共享给你的 Cursor 团队，大家和同一个 Bot 聊天。选对方式，分享才安全省心；选错了，要么对方改不了，要么把不该给的东西给了出去。

::: callout 一句话记住本期
想让每人一份自己的就发模板，想让大家共用同一个就共享 Bot；分享前先清点里面有什么，因为共享出去的东西，在每个人的聊天里都会生效。
:::

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接发给你的 Bot。

### 技巧一：先分清模板和共享 Bot {#tip1}

先看你想要的结果，再选方式。

模板适合：

::: props
- 各用各的: 每个人得到自己的副本，之后各自修改
- 分享方式: 一个链接，对方在 x.ai 上预览后添加到自己的 Grok Bot
- 对方得不到: 你的电脑、登录和聊天记录
:::

共享 Bot 适合：

::: props
- 大家共用: 团队成员和同一个 Bot 聊天，共享不会复制
- 对象: 面向有 Grok Bot 的 Cursor 团队成员
- 隐私: 每个人和它的聊天互相私密，所有者和 Manager 也看不到
:::

共享 Bot 的链接对所有人打开的是同一个 Bot，这和模板「每人一份副本」是两回事。另外，共享 Bot 始终运行在云端，跑在你自己电脑上的 Bot 无法共享。

::: prompt
请帮我判断下面这个 Bot 该发「模板」还是「共享给团队」：
Bot 的用途：[一句话]
使用的人：[团队成员 / 朋友同事 / 公开]
对方是否需要各自改它：[是/否]
是否都在同一个 Cursor 团队里：[是/否]
这个 Bot 是否跑在我自己的电脑上：[是/否]
用三句话给出建议并说明理由。先不要创建模板，也不要改任何共享设置。
:::

### 技巧二：发模板：Share → Create a copy → Publish {#tip2}

官方给出的步骤很短：

::: steps
- 打开详情 | 点聊天顶部的 Bot 名字，打开 Bot 详情。
- 创建副本 | 选 Share，再选 Create a copy，Bot 会生成一份模板并发到聊天里。
- 发布并复制 | 在模板卡片上选 Publish，再选 Copy link，把链接发出去。
- 对方添加 | 对方打开链接在 x.ai 上预览，选 Add to Grok Bot，需要有 Grok Bot 应用才能完成添加。
:::

在 iPhone 和 Android 上，打开 Bot 的菜单选 Share as Template。发布之后，同一个 Share 菜单里还有 View template details、Update template（把最新改动推到共享的那份）和 Delete Template（关掉链接）。

新的模板链接是公开的；如果团队只允许团队内分享，或关闭了模板分享，应用里就不会出现 Create a copy。

::: prompt
我想把这个 Bot 做成模板分享给别人。请先只做检查、不要发布：
1. 列出它的身份、描述、技能和 Routines 里有哪些内容会被模板带出去；
2. 标出其中可能含有 API Key、内部网址、客户数据或其它不能公开的内容；
3. 给出我需要先改掉的清单。
等我确认清理完成后，我再让你继续 Create a copy 和 Publish。
:::

### 技巧三：发布前，把「像公开文档」当标准清理 {#tip3}

模板链接会暴露 Bot 的共享配置，也就是身份、描述、技能和 Routines。官方的建议是：去掉 API Key、内部网址、客户数据，以及任何你不会写进公开文档的东西。

::: props
- 会被带出去: 身份、描述、技能、Routines
- 不会被带出去: 你的电脑、登录和聊天记录
- 公开链接: 任何拿到链接的人都能打开
- 团队内链接: 只有你团队的成员能打开
:::

官方安全页也强调：分享 Bot 不是安全边界。公开链接让别人复制配置，却不是在保护里面的内容，所以别指望「反正对方拿不到登录」就把密钥写在技能或描述里。

另外，通过模板添加别人的 Bot 时，会看到第三方 Bot 条款；模板是其他用户创建的，不是 Grok Bot 创建的，要像审视技能或软件一样审视它。

::: prompt
请把这个 Bot 要分享出去的内容按「写进公开文档」的标准过一遍：
1. 逐项检查身份、描述、技能、Routines；
2. 凡是密钥、内部网址、客户数据、个人信息，都列出位置并建议改成占位符；
3. 密钥类内容不要放在这些地方，应放到 Vault 或安全卡片里；
4. 汇总一份「清理前 / 清理后」对照，供我确认。
我确认前不要修改任何内容，也不要发布。
:::

### 技巧四：共享 Bot：谁能用、用谁的应用、谁买单 {#tip4}

共享 Bot 的步骤：点聊天顶部的 Bot 名字，选 Share。在 Who has access 下，选你的团队给所有人用，或选 People you invite 只给指定的人和群组。再通过 Add people or groups 添加人，并在 Add as 里选：

::: props
- Collaborator: 可以和这个 Bot 聊天
- Manager: 还能修改它的指令、技能、记忆和应用
- 所有者和 Manager: 始终可以使用这个 Bot
:::

几条要记住的规则：

::: steps
- 应用和密钥 | 共享 Bot 使用所有者添加的应用和密钥，对每个聊天的人都一样；只加你愿意让被分享者都用的。
- 你的个人账号 | 在你自己的聊天里它也能用你的应用，但用你的个人账号前会问你：Allow once、Always allow 或 Skip。
- 用量 | 它回复谁，就消耗谁的 Grok Bot 用量，你自己的额度生效。
- 审批 | 它在做风险操作前问被回复的人；群聊里也只有被回复的那个人能批。
- 队友怎么找 | 点 + 再选 Browse shared Bots，选 Add 放进侧边栏，也可以打开队友发来的链接选 Start a chat。
:::

共享之前，先检查这个 Bot 里的应用、密钥、技能和文件，因为它们会在每个队友的聊天里生效。

::: prompt
我准备把这个 Bot 共享给团队。请先只做盘点，不要改共享设置：
1. 列出它现在连着的应用、保存的密钥、技能和文件；
2. 对每一项标注「所有被分享的人都能用到」后，我是否应该保留；
3. 建议谁当 Collaborator、谁当 Manager（角色用 [角色名] 代替）；
4. 提醒我共享后它回复谁就消耗谁的用量。
给我一张保留 / 移除表，等我确认。
:::

### 技巧五：把共享 Bot 放进 Slack {#tip5}

所有者或 Manager 在共享之后可以把它接进 Slack：

::: steps
- 打开详情 | 点聊天顶部的 Bot 名字。
- 连接 Slack | 找到 Bring to your team's Slack，选 Connect。
- 管理员批准 | 如果显示 Awaiting admin approval，需要 Slack 工作区管理员批准这个应用。
- 队友关联账号 | 每位队友先在 Settings → General → Shared Bots 里选 Link，关联自己的 Slack 账号。
- 开始用 | 显示 Connected 后，队友可以直接给它发消息，或在频道里提到它。
:::

在 Slack 频道、线程和群聊里，共享 Bot 只用所有者的应用，并在用到你的账号前先问你；在频道、线程、群私信和群聊里，它使用自己的一台共用电脑。在线程里，Bot 会记录每条消息是谁让它发的，线程里任何人都可以问它是谁要求的。审批卡 Review an action 上有 Allow once、Deny 和 View details，只有提问的人能回答。

::: prompt
我们打算把这个共享 Bot 接进团队的 Slack。请先帮我准备一份上线前检查清单，先不要执行任何连接操作：
1. 我（所有者或 Manager）需要做的步骤；
2. 需要 Slack 管理员批准时我该怎么说明；
3. 通知每位队友先 Link 自己 Slack 账号的一段话；
4. 提醒大家：频道里它只用所有者的应用，用到个人账号前会先问。
只给清单和文案，等我确认。
:::

## 几个必须知道的边界 {#limits}

::: steps
- 共享 Bot 只在云端 | 跑在你自己电脑上的 Bot 无法共享；共享 Bot 加入群聊时，也不能和跑在你自己电脑上的 Bot 同处一个群。
- 模板链接默认公开 | 除非团队只允许团队内分享，否则新链接任何人拿到都能打开。
- 分享不是安全边界 | 公开链接不保护里面的内容，不要把密钥、客户数据、内部网址放进去。
- 共享的东西人人可用 | 所有者添加的应用、密钥、技能、文件在每个队友的聊天里都生效。
- 删除影响整个团队 | 只有所有者能删共享 Bot，删除后队友会失去它及其聊天和 Routines，且无法撤销。
- 共享 Bot 不能当主 Bot | 手机上可以聊天和回应 Allow 卡片，但它不能作为你的 Primary Bot。
- 团队可能限制模板分享 | 管理员可以关闭公开模板，这时应用里不会出现 Create a copy。
:::

## 实战案例：虚构的“周报小队”怎么分享 {#case}

延续前几期的虚构阵容（并非任何人的真实配置）：一位运营同学调好了一个“周报助手”Bot，想让同组同事一起用，另外也想发给一位外部朋友试试。

| 对象 | 方式 | 理由 | 分享前要做的事 |
| --- | --- | --- | --- |
| 同组同事 | 共享 Bot | 大家都用同一个，应用和技能统一维护 | 盘点应用、密钥、文件；指定一位 Manager |
| 外部朋友 | 模板 | 对方不在团队，需要自己的副本 | 清掉描述和技能里的内部网址与数据 |
| 同组 Slack 频道 | 共享 Bot + 接入 Slack | 频道里直接提到它 | 管理员批准；每人 Link 自己的账号 |
| 暂不分享的内容 | 保留在私有 Bot | 含个人账号与私密数据 | 不放进共享 Bot，不进模板 |

### 亮点：先盘点，再选方式，最后分步放行 {#case-flow}

她没有一上来就发链接，而是先让 Bot 盘点内容，再按对象选择方式，每一步都等她确认。

::: flow
- 我 | 让 Bot 盘点要分享的内容 | person
- 周报助手 | 列出应用、密钥、技能、文件和 Routines
- 周报助手 | 标出不能公开或不该共享的内容
- 我 | 确认清理，并选模板或共享
- 周报助手 | 按我的选择生成模板或调整共享范围
---
- 我 → 周报助手：先盘点，别发布
- 周报助手 → 我：清单与风险标注
- 我 → 周报助手：确认清理项
- 周报助手 → 我：请示是否 Publish / 是否 Share
- 我 → 周报助手：确认后再放行
:::

对外部朋友，她用的是模板并去掉了内部信息；对同组同事，则共享同一个 Bot 并指定了 Manager。两种方式没有混用。

::: prompt
你是这个“周报助手”。请按下面顺序处理分享需求，每一步都停下来等我确认：
1. 盘点应用、密钥、技能、文件和 Routines；
2. 标出不能公开或不应共享的内容；
3. 对「同组同事」给出共享方案，对「外部朋友」给出模板方案；
4. 在我确认之前，不要 Publish、不要改共享范围、不要发任何链接。
只给盘点和方案。
:::

## 社区玩法精选 {#community}

本期整理了几类常见、好上手的用法，供大家参考。都是通用思路，具体内容换成你自己的。

### 先做一个“干净版”再分享 {#c1}

把要分享的 Bot 先整理成只含通用说明与通用技能的版本，再发模板，私人内容留在自己的 Bot 里。

### 清理清单存成片段 {#c2}

把「身份、描述、技能、Routines 逐项检查」写成固定片段，每次分享前直接让 Bot 过一遍。

### 共享前先指定 Manager {#c3}

共享给团队时，先决定谁能改指令、技能和应用，避免所有人都能动同一份配置。

### 外部用模板、内部用共享 {#c4}

对团队外的人发模板，对团队内的人共享同一个 Bot，两种方式分开，不容易搞混。

### 模板更新后通知对方 {#c5}

用 Update template 推送新改动后，主动告诉别人；官方文档没有说明已经添加的副本是否随之变化。

## 本期小练习 {#exercise}

花 15 分钟，拿一个虚构或无敏感信息的 Bot 练一遍分享流程。

::: steps
- 选对象 | 写下谁要用这个 Bot，判断该发模板还是共享给团队。
- 做盘点 | 让 Bot 列出身份、描述、技能、Routines，以及共享场景下的应用、密钥和文件。
- 做清理 | 把密钥、内部网址、客户数据换成占位符，需要保密的放进 Vault 或安全卡片。
- 走一遍流程 | 模板走 Share → Create a copy → Publish；共享走 Share → Who has access → Add as。先不要真的发给别人。
- 复盘 | 检查有没有把模板和共享混着用，以及共享后有没有东西不该让所有人用到。
:::
