qa:
  - q: 几个 Bot 共用一台电脑，会不会互相看到对方的东西？
    a: 会。按官方文档，文件、浏览器 Cookie 和登录会话、命令行凭据对你账号下所有 Bot 都可见，所以不想让某个 Bot 用到的凭据或文件，就不要放到这台电脑上。不同用户之间则是严格隔离的。

## 本期导读 {#intro}

前三期讲了怎么分工、怎么定时、怎么把做法存成技能。这些最后都要落到一个地方去执行：Bot 的那台云端电脑。

根据官方文档，你的 Bot 在一台持久的云端电脑上工作，上面有浏览器、命令行和文件系统。你合上笔记本，它照样干活；文件、登录和浏览器会话在任务之间都会保留。搞清楚这台电脑怎么共享、什么时候该用连接应用、什么时候该用浏览器、敏感步骤怎么交接，很多“Bot 怎么又卡住了”的问题就不会再出现。

::: callout 一句话记住本期
一台电脑，所有 Bot 共用；有应用先用应用，没有再用浏览器；密码不进聊天，卡住的那一步你来接管；电脑出问题从最轻的办法开始。
:::

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接发给你的 Bot。

### 技巧一：把“一台电脑大家共用”当成前提 {#tip1}

官方文档说得很清楚：你账号下的每个 Bot 用的都是同一台电脑。

::: props
- 浏览器: Cookie 和已登录的会话是共享的
- 文件: 所有 Bot 都能看到
- 命令行凭据: 也是共享的
- 接力: 一个 Bot 可以接着另一个 Bot 保存下来的工作继续做
:::

好处是交接不用重复配置：研究员存下的资料，撰稿人直接就能打开。代价是这台电脑属于你的账号，而不是某一个 Bot。官方的建议是：如果某个凭据或文件不该被账号下的其它 Bot 使用，就不要把它放到这台电脑上。

每个 Bot 在这台电脑上有自己的屏幕，所以多个 Bot 可以同时用浏览器和桌面工具；不过一个 Bot 同一时间只能在自己的屏幕上跑一个操作电脑的任务。这些屏幕是各自的工作台，不是安全隔离。

文件方面，官方建议把要长期保留的项目文件放进共享工作区，按项目分好文件夹；临时目录、手动装的软件包这些都当作随时可能被替换的东西，重要结果要复制到工作区或者直接附在对话里。

::: prompt
请帮我整理一下你这台电脑上和 [项目名] 有关的文件：
1. 列出散落在临时目录里、但看起来需要长期保留的文件；
2. 建议一个清楚的项目文件夹结构，把它们归进去；
3. 如果发现密钥、凭据之类不该放在共享电脑上的东西，只告诉我位置，不要打开内容。
先给我方案，我确认后再移动。
:::

### 技巧二：有应用先用应用，浏览器兜底 {#tip2}

连接应用给 Bot 一个结构化的方式去用 Gmail、Notion、Slack 这类服务，官方说只要有对应的应用，它就比在网站上一路点击更可靠。没有应用的服务，或者应用没覆盖的可视化流程，再用浏览器。

连接的步骤在侧边栏里：

::: steps
- 打开连接应用 | 从侧边栏打开连接应用（Connect apps），或者点聊天里弹出的连接卡片。手机上点左上角头像，再选连接应用。
- 找到并添加 | 浏览或搜索要用的应用，然后添加。
- 完成授权 | 出现授权（Authorize）或认证（Authenticate）时，在浏览器里登录对应的服务。
- 卡住了就重来 | 登录没完成时，在应用上点重新连接（Reconnect），或在聊天卡片上点重新打开（Reopen）。
- 确认已安装 | 确认这个应用出现在已安装（Installed）里。
:::

有两点特别容易踩坑。第一，“已添加”只表示装上了，不代表已经登录；Bot 说缺某个应用时，打开这个应用，如果显示需要认证（Needs auth）或已断开（Disconnected），点认证。第二，连接好的应用对你所有的 Bot 都可用，聊天里输入 @ 就能把应用挂到当前任务上。

也可以直接让 Bot 帮你装，比如说“添加 Linear 应用”：它会在目录里搜索、装到你的账号上，需要你登录时弹出连接卡片，下一条消息起就能用。

::: prompt
接下来这项工作要用到 [服务名]。请先检查：
1. 有没有对应的连接应用，有的话帮我添加，需要我登录时弹卡片给我；
2. 如果没有应用，告诉我你打算用浏览器做哪些步骤；
3. 这个应用能做什么、不能做什么，列给我看。
确认之前不要往这个服务里写入或发送任何东西。
:::

### 技巧三：登录交给安全流程，卡住的那一步你来接管 {#tip3}

按官方文档，Bot 需要登录网站时有一个固定顺序：先用你在 Vault 里保存的登录，再用已连接的密码管理器（比如 1Password），最后通过安全表单（Secure Form）问你。Vault 和安全表单里的值是直接填进网页的，Bot 自己看不到。

有些步骤表单填不了，这时 Bot 会把电脑交给你：

::: props
- 单点登录或通行密钥: 需要你本人完成
- 过不去的验证码: Bot 试过但没通过
- 另一台设备上的确认或二维码: 比如手机上点批准
- 银行卡验证: 支付时的额外校验
- 明确要求真人的网站: 按网站的要求来
:::

处理方法是：打开电脑视图，接管控制，只完成被卡住的那一步，然后告诉 Bot 继续。浏览器会话会保留，而且是所有 Bot 共享的，所以你帮一个 Bot 登录过，其它 Bot 通常也不用再登。

::: proscons
#### 这样做
- API 密钥等机密，在 Bot 弹出的安全输入卡片里填写
- 会话过期或要求再次验证时，让 Bot 暂停并通知你
- 只接管被卡住的那一步，其余交还给 Bot

#### 别这样做
- 把密码或一次性验证码贴进普通聊天
- 让 Bot 想办法绕过网站的验证
- 接管后顺手做一堆别的操作，让 Bot 不知道发生了什么
:::

::: prompt
接下来要登录 [网站名] 完成 [任务]。请遵守：
1. 先用已保存的登录或已连接的密码管理器，没有就用安全表单问我，不要让我在聊天里发密码；
2. 遇到单点登录、通行密钥、二维码或过不去的验证码，停下来告诉我卡在哪一步，我来接管；
3. 会话过期或要求再次验证时，暂停并通知我，不要尝试绕过。
:::

### 技巧四：给 Bot 一个它自己的邮箱 {#tip4}

你可以在 mail.grokbot.com 下认领一个邮箱地址给 Bot 用。有了它，Bot 可以用自己的地址注册服务、在你同意后取验证码或验证链接，收集收据、订阅邮件和报告并给你做摘要，帮你起草邮件，还能在收到邮件时触发 Routine。

最简单的认领方式是直接说“给你自己弄一个邮箱地址”：Bot 会问你想要什么名字、检查是否可用，再弹出审批卡片，你批准之前什么都不会认领。几条规则值得记住：

::: props
- 只有一个: 每个账号一个地址，不能改名、不能删除，地址也永远不会再分配给别人
- 加号别名: 发到“名字+标签”的邮件进同一个收件箱，可以给每个服务一个别名；监听某个别名的 Routine 只对发到这个别名的邮件运行
- 没有收件箱界面: 也没有新邮件通知，想看就问 Bot“今天收到了什么”
- 收到邮件不会自动唤醒 Bot: 要处理就配一个监听邮件的 Routine，默认只对通过标准邮件认证的发件人运行
- 发送有门槛: Routine 里或不是你主动要求发送的邮件，只会存成草稿，等你点发送，没有无人值守发送的选项
:::

别名只是标签，不是锁，谁都可以往里发信。所以一个只该处理特定发件人邮件的 Routine，要记得加上发件人过滤。Bot 也会把别人发来的邮件当作信息，而不是指令。

::: prompt
请帮我规划一下你的邮箱怎么用：
1. 我会用它注册 [服务一]、[服务二]，各给一个加号别名，列成表给我；
2. 为 [服务一] 的账单邮件配一个 Routine：只处理来自 [发件人或域名] 的邮件，每封整理成一行摘要发给我；
3. 任何回复或对外发送都只存草稿，等我确认。
先给方案，我确认后再动手。
:::

### 技巧五：电脑连不上，从最轻的办法开始 {#tip5}

电脑控制在设置里的电脑（Settings → Computer）一栏，那里有更新、恢复和重置三个动作。官方给的处理顺序是从最不具破坏性的开始：

::: steps
- 等一等再重试 | 显示正在重连或无法连接时，先等待，再点重试（Retry），或者重新打开对话。重连期间 Bot、文件和登录都是安全的，这时不要重置。
- 完全退出重开 | 彻底退出 Grok Bot 再打开，并检查应用更新。Mac 上要从菜单栏选退出，而不只是关窗口。
- 更新电脑 | 如果设置里提供了更新 Bot 的电脑，就用它。
- 恢复电脑 | 还是连不上，或者更新看起来卡住了，再用恢复（Recover）。它会先尽量保存，再用你保存的数据重建一台新电脑。
- 最后才重置 | 只有上面都试过了，才用重置（Reset）。
:::

更新和重置正在进行时，不要再发起第二次，反复重置可能会打断还没完成的恢复。不管哪种操作，对话都存在电脑之外，即使重置也不会丢；但手动安装的软件和软件包可能需要重装。如果 Bot 最近消失了或保存失败，官方建议先联系支持，再考虑恢复或重置。

::: prompt
你的电脑刚才一直连不上，现在恢复了。请帮我检查：
1. 最近在做的 [项目或任务] 的文件还在不在；
2. 之前装过、现在需要重新安装的工具或依赖有哪些；
3. 哪些网站的登录需要我重新处理。
只列清单和建议，需要重装或重新登录的先问我。
:::

## 几个必须知道的边界 {#limits}

::: steps
- 应用不会扩大权限 | 连接应用用的是你授权的那个账号，只能做这个账号本来就能做的事，不能提高你的访问权限，也不能改共享设置。
- 应用令牌不在电脑上 | 应用的授权令牌保存在后端，Bot 调用工具时拿不到令牌本身。
- 团队策略优先 | 被团队管理员禁用的应用会显示已被管理员禁用，需要找管理员开启。
- 公开的 X 内容不用连接 | Bot 可以只读地搜索和阅读 X 上公开的内容；要读你的私信、书签或首页时间线，才需要添加 X 插件并登录。
- 你的本地电脑是另一回事 | 云端电脑和你面前的电脑是分开的。Bot 只有在开启了相应能力并经你批准后，才会在你的本地电脑上运行命令，默认每条都要问你。
:::

## 实战案例：一支共用一台电脑的通讯小队 {#case}

延续前几期的虚构阵容（并非任何人的真实配置）：一个小团队每周出一期通讯，同时维护一个业余小应用。这次他们把每个 Bot 要用的应用和登录理了一遍：

| Bot | 主要用的连接应用 | 需要浏览器的地方 | 要你接管的步骤 |
| --- | --- | --- | --- |
| 资料研究员 | 公开 X 内容、云端文档 | 没有应用的资讯网站 | 少数要求真人验证的网站 |
| 撰稿人 | 文档类应用 | 排版预览 | 无 |
| 审稿人 | 文档类应用 | 打开原文核对来源 | 付费墙网站的登录 |
| 规划师 | 日历 | 无 | 无 |
| 构建师 | 代码托管平台 | 部署后台 | 单点登录 |

### 亮点：一次登录，全队受益 {#case-flow}

审稿人要核对的一个资料网站只能用浏览器登录。它用安全表单请你填了一次，登录会话就留在了共享浏览器里，之后资料研究员去同一个网站找资料时，直接就能打开，不用再问你。

::: flow
- 审稿人 | 需要登录资料网站
- 我 | 在安全表单里填写登录信息 | person
- 共享浏览器 | 保留登录会话
- 资料研究员 | 直接打开同一网站
---
- 审稿人 → 我：请求登录
- 我 → 共享浏览器：填写后会话保留
- 共享浏览器 → 资料研究员：复用已有会话
- 共享浏览器 ⇢ 我：会话过期时再次请求
:::

反过来也提醒他们：既然登录是共享的，不想让所有 Bot 都能用的账号，就别在这台电脑上登录。

::: prompt
你是这个团队的规划师。请帮我盘点一下：资料研究员、撰稿人、审稿人、构建师各自用到了哪些服务。
给我一张表：服务名、有没有连接应用、目前是用应用还是用浏览器、登录方式、是否适合所有 Bot 共用。
标出能从浏览器换成连接应用的地方。先给方案，不要安装或登录任何东西。
:::

## 社区玩法精选 {#community}

本期整理了几类常见、好上手的用法，供大家参考。都是通用思路，具体内容换成你自己的。

### 一个 Bot 下载，另一个 Bot 处理 {#c1}

因为文件在共享电脑上，一个 Bot 把报表下载到项目文件夹，另一个 Bot 直接接着整理、出图，中间不用你转手。

### 给每个服务一个邮箱别名 {#c2}

注册不同服务时用不同的加号别名，再给关心的那个别名配一个带发件人过滤的 Routine，收据、账单就能分门别类地汇总。

### 先问“有没有应用” {#c3}

接新活之前，先让 Bot 检查要用的服务有没有连接应用。能用应用的部分更稳定，浏览器只留给真正需要的地方。

### 把接管步骤写清楚 {#c4}

在技能或 Routine 里写明：遇到单点登录、验证码或二维码就停下来通知你，而不是反复尝试。这样它卡住时你一眼就知道要做什么。

### 电脑出问题时的检查清单 {#c5}

恢复或更新之后，让 Bot 按清单核对项目文件、需要重装的依赖和需要重新登录的网站，比等到下次任务失败再发现要省事。

## 本期小练习 {#exercise}

花 15 分钟，把你的 Bot 用到的应用和登录理一遍。

::: steps
- 盘点 | 让 Bot 列出你最近交给它的工作用到了哪些服务。
- 换成应用 | 有连接应用的服务，按技巧二添加并完成认证。
- 查登录 | 确认没有在聊天里发过密码；需要机密的地方改用安全输入卡片。
- 清理 | 不该被所有 Bot 共用的凭据和文件，从电脑上移走。
- 记住顺序 | 把技巧五的处理顺序存下来，下次电脑连不上时照着做。
:::
