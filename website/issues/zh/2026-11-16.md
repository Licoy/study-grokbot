  - q: Bot 突然不回话了，是坏了吗？
    a: 先看它说了什么。如果提示用量已达上限，说明每周用量用完了，每周会重置；如果是 Bot failed to respond 或 Model provider is overloaded，而状态页没有故障，稍等再发一次，还不行就完全退出重开 Grok Bot。
  - q: 电脑连不上，能直接点 Reset 吗？
    a: 不建议。Reset 是最后一步。先等待并点 Retry，再完全退出重开，有更新就更新电脑，仍不行再用 Recover computer。Recover 和 Reset 都会保留已保存的 Bot、文件和登录，但会删掉装过的应用和软件包，电脑连不上时最近的改动也可能丢失。

## 本期导读 {#intro}

前面十几期讲的都是怎么把 Bot 用起来。但真正天天在用的人都遇到过这些时刻：Bot 半天不回话，电脑卡在 Reconnecting，昨天的 Routine 没跑，或者侧边栏里少了一个 Bot。这时候最容易犯的错，是一着急就点 Reset。

官方文档专门有一页“Troubleshooting”，开头第一句就是：从最轻的一步开始。本期把这一页整理成 5 条技巧：先做最轻的检查、按顺序恢复电脑、找回“消失”的聊天和文件、处理卡住的 Bot 和没跑的 Routine、解决网站和应用连不上，最后讲清怎么高效地联系支持。

::: callout 一句话记住本期
先退出重开、先看状态页、先让 Bot 自己说清卡在哪；Reset 永远是最后一步，聊天记录不会因为电脑出问题而消失。
:::

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接用。

### 技巧一：先做最轻的一步，再看状态页 {#tip1}

大多数问题完全重启一次就能好：彻底退出 Grok Bot（Mac 上从菜单栏选 **Quit**，而不只是关掉窗口），重新打开再试。应用断开时，Bot 在云端的工作可以继续。

::: props
- 服务是否故障: 打开 status.cursor.com 看 **Grok Bot** 这一行，应用里不显示服务状态；有故障就等修复后再发消息，不要 Reset 电脑，也不要重装应用
- 暂时没响应: 状态页没有故障，但 Bot 提示 **Bot failed to respond** 或 **Model provider is overloaded**，稍等再发一次，仍不回复就完全退出重开
- 设备掉线: 看到 **You're offline**，说明你的设备没有网络，Bot 在云端照常工作，聊天暂时显示 **Showing saved messages**
- 用量用完: Bot 提示已达用量上限并不是坏了，每周用量会重置；想马上继续，可以购买额度或换更大的套餐
- 版本太旧: 版本超过 14 天且有新版本时，应用会显示 **Update required**，选 **Update** 再 **Restart to update**，期间 Bot 照常在云端运行
:::

::: prompt
我这边好像出问题了，请帮我做一次快速自检：
1. 告诉我你现在能不能正常连上自己的电脑；
2. 列出你最近一次没完成的任务，以及卡在哪一步；
3. 如果需要我操作（比如登录、审批、更新），说清是哪一步。
只汇报，先不要重试任何任务。
:::

### 技巧二：电脑连不上，按顺序恢复，Reset 放最后 {#tip2}

电脑暂时连不上时，Bot 的资料和已保存的对话都不会丢：聊天存放在电脑之外，Bot、文件和登录在重连期间都是安全的。如果电脑的卡片显示 **Unreachable** 而聊天还能用，可能是 VPN 或公司防火墙挡住了连接，换个网络试试。

::: steps
- 等待并重试 | 显示 **Reconnecting** 或 **Couldn't Reach Grok Bot's Computer** 时，先等一等，再点 **Retry**；这期间不要 Reset。
- 完全退出重开 | 彻底退出 Grok Bot，再重新打开。
- 有更新就更新 | 打开 **Settings → Computer**，选 **Update Bot's Computer**。
- 再试 Recover | 仍连不上，或更新看起来卡住了且出现了 **Recover computer**，再选它。
- 最后才 Reset | 以上都试过再用 **Reset**；手机上在 **Settings → Bot → Bot Computer** 里有 **Reset Computer**，更新和 Recover 要在桌面端操作。
:::

几种操作会保留和丢掉的东西不一样：

| 操作 | 保留 | 会丢 |
| --- | --- | --- |
| 软件更新 | 全部，包括装过的应用 | 无 |
| 电脑整体更新 | Bot、文件和登录 | 装过的应用和软件包 |
| Recover computer | 已保存的 Bot、文件和登录 | 装过的应用和软件包；正在跑的工作会中断；连不上时最近的改动可能丢失 |
| Reset | 上次保存的数据 | 和 Recover 一样 |

`node_modules`、Python 虚拟环境这类项目文件夹不会被保存，更新、Recover 或 Reset 之后要重新安装。Update 或 Reset 正在进行时，不要再点第二次；Recover 或 Reset 失败时，点一次 **Retry Recovery** 或 **Retry Reset**，还不行就停下，联系支持。如果最近有 Bot 消失或保存失败，先联系支持，再考虑 Recover 或 Reset。

::: prompt
我准备更新你的电脑，请先帮我做一次盘点：
1. 列出电脑上我们自己装过的应用和软件包，以及安装它们的命令；
2. 列出需要重新安装依赖的项目文件夹；
3. 把这份清单存成电脑上的一个文件，更新完成后照着帮我恢复。
:::

### 技巧三：聊天、Bot 或文件“不见了”，先别动手 {#tip3}

它们通常没有被删除。官方明确说：不要用 **Recover** 或 **Reset** 去找它们。按下面的顺序查：

::: steps
- 完全退出重开 | 先彻底退出 Grok Bot，再重新打开。
- 换台设备看看 | 在手机或另一台电脑上登录同一账号，Bot 和对话在同一账号的设备之间是共享的。
- 找隐藏的 Bot | 桌面端在侧边栏打开 **Hidden Bots**，手机上打开 **Show Hidden Bots**；**Hide from sidebar** 只是从列表里移走，被隐藏的 Bot 照常运行、记录都在。桌面端选 **Show in sidebar**，手机上选 **Unhide** 就能放回来。
- 确认账号 | 确认登录的是同一个 Cursor 账号，而不是另一个账号。
:::

文件方面：在电脑里删文件，包括 `rm -rf`，都不会删掉聊天。Grok Bot 会为已同步的电脑数据保留一份持久副本，重新打开电脑时会从中恢复，已同步的文件通常能回来；Recover 之后电脑仍是空的，就别再在里面做改动，直接联系支持。只存在你自己 Mac 或 Windows 电脑上的文件不在保障范围内，记得自己备份。电脑磁盘快满时，Bot 会在聊天里提醒一次，列出最大的文件和文件夹，你同意才会删，磁盘空间不足也不等于丢数据。

::: prompt
我在侧边栏里找不到 [某个 Bot] 了。请帮我确认：
1. 你能不能看到我账号下所有 Bot 的列表，其中有没有它；
2. 它是不是被隐藏了，如果是，告诉我在哪里把它放回来；
3. 在我确认之前，不要恢复、重置或删除任何东西。
:::

### 技巧四：Bot 卡住、审批过期、Routine 没跑 {#tip4}

Bot 看起来卡住时，多半是在等你：

::: props
- 看状态: 侧边栏和对话里的状态，**Needs attention** 表示有问题、审批或交接在等你
- 看屏幕: 打开电脑，看 Bot 是不是停在某个网页上
- 找请求: 看有没有提问、审批、登录、验证码或机密请求在等你处理
- 改方向: 思路不对就发一句简短的纠正
- 叫停: 不需要继续了，直接发一句“现在停下”
:::

审批卡过期也很常见：你在场的对话里发起的审批会一直等你；而 Routine、触发器或其他 Bot 的消息这类你不在场时发起的工作，审批大约 30 分钟后显示 **Expired**，动作不会执行。给跑 Routine 的 Bot 打开 **Notifications**，信得过的动作选 **Always allow**，过期后让 Bot 再做一次。总是要你审批的动作，去 **Settings → General → Bot** 的 **Custom Rules** 里看有没有匹配的 **Ask first** 规则，包括管理员要求的团队规则；**Ask first** 优先于 **Allow automatically**。

Routine 没跑时，打开它逐项核对：

::: steps
- 是否启用 | 不是 **Paused** 状态。
- 时间对不对 | **When to run** 里的时间和时区是你想要的。
- Bot 还在 | 负责它的 Bot 没被删除。
- 应用还连着 | 用到的应用仍处于已授权状态，电脑也能访问到数据来源。
- 用量和账号 | 用量或账号访问没有被暂停。
- 看运行记录 | 在最近的运行记录里找失败原因；**Test** 可能真的执行对外动作，只用安全的输入测试。
:::

如果一个 Routine 没有暂停、也没报错，却 24 小时以上都没跑，带上 Bot 名称和 Routine 详情去提交问题报告。

::: prompt
我的 [某个 Routine] 今天早上没有按时运行。请逐项帮我检查：
1. 它是否启用、下一次运行时间和时区是什么；
2. 它用到的应用是否都还连着；
3. 最近几次运行有没有失败，失败原因是什么。
先只汇报，不要手动执行它，因为它可能会对外发消息。
:::

### 技巧五：网站登录、连不上与应用授权 {#tip5}

网站反复要求登录时，自己接管一次：在 **Computer** 卡片上点 **Take over**，自己登录并完成双重验证或验证码，确认已登录的页面加载好了，再点 **I'm done**，让 Bot 从当前页面继续。不要把密码或验证码贴进普通聊天。笔记本或手机上的指纹、面容、Windows Hello 和通行密钥在 Bot 的电脑上用不了。

::: props
- 网站超时或连不上: Bot 的电脑经由 Cursor 的共享网络上网，有些网站会断开它的连接；Update、Recover 和 Reset 都改变不了这一点，可以在 **Settings → Computer → Your computer** 里打开 **Route traffic through this computer**，让 Bot 的浏览器走你桌面电脑的网络
- 应用装了但用不了: 显示 **Added** 只代表装好了，不代表已登录；在侧边栏打开 **Connect apps**，看状态是 **Needs auth** 或 **Disconnected** 就点 **Authenticate**，是 **Disabled by team admin** 就找团队管理员
- 授权卡住: 连接卡片写着在等授权就点 **Reopen**，授权没完成或失败就点 **Retry**，按钮变成 **Reconnect** 就点它
- 还是不行: 选 **Remove**，重新添加应用再登录
:::

::: prompt
你刚才打不开 [某个网站]，请先别反复重试，按下面的顺序帮我判断：
1. 是要求登录，还是超时或连接错误；
2. 如果需要登录，弹出接管请求，告诉我是哪一步，我来完成；
3. 如果是连接问题，告诉我具体的报错，我再决定要不要让流量走我的电脑。
:::

## 联系支持前，备好这些 {#support}

桌面端在账号菜单里选 **Support → Send Feedback**，问题出在当前对话时，勾上 **Include current conversation ID**；手机上在 **Settings** 里点 **Send Feedback**，问题出在某个 Bot 时，选中它并保持 **Include Bot ID** 打开。需要支持团队帮忙时，用 Grok Bot 账号的邮箱写信到 support@x.ai。

::: steps
- 版本信息 | 在账号菜单选 **Support → About**，再点 **Copy version info**，会复制版本、发布通道和系统。
- request ID | 右键出错的消息选 **Copy request ID**，或悬停后打开 **More message actions** 再选；没有这个选项时，附上报错文字和截图。
- 现场信息 | 你想做什么、Bot 或 Routine 的名称、准确的报错或截图、大概的时间和时区。
- 已试过的步骤 | 比如重试、重启应用、更新电脑。
- 绝对不附 | 密码、一次性验证码、私钥或任何机密值。
:::

## 几个必须知道的边界 {#limits}

::: steps
- Reset 是最后一步 | 服务故障、网站连不上、聊天不见了，Reset 都解决不了，还可能丢掉最近的改动。
- 项目依赖要重装 | 更新、Recover 或 Reset 之后，`node_modules` 和 Python 虚拟环境要重新安装。
- 本机文件自己备份 | 只存在你自己电脑上的文件不在保障范围内。
- 重装通常没用 | 登录反复失败时，重装应用通常解决不了；先更新应用、清理浏览器缓存再试。
- 有些问题只能找支持 | 部分会话和账号关联问题无法自己解决，带上准确的报错和已试步骤联系支持。
:::

## 实战案例：虚构的“晨报助手”某天没发晨报 {#case}

延续前几期的虚构阵容（并非任何人的真实配置）：一位独立开发者配了一个 Bot“晨报助手”，每天早上用 Routine 汇总前一天的产品反馈，整理成一份晨报。某天早上，晨报没有出现。

| 环节 | 做法 | 注意点 |
| --- | --- | --- |
| 先看状态页 | Grok Bot 一行没有故障 | 排除服务问题，不重装、不 Reset |
| 看侧边栏 | 晨报助手显示 Needs attention | 原来有一张审批卡 |
| 看审批卡 | 已显示 Expired，夜里没人批 | 过期的动作没有执行 |
| 查 Routine | 已启用，时间和时区都对 | 定时本身没问题 |
| 补救 | 让晨报助手重做一次，并打开它的 Notifications | 对信得过的读取动作选 Always allow |

### 亮点：十分钟找到原因，没碰一下 Reset {#case-flow}

从发现晨报没来到补发出去，全程只是查看和对话，电脑一点没动。

::: flow
- 我 | 发现晨报没来 | person
- 晨报助手 | 自检并说明卡点
- 我 | 批准并打开通知 | person
- 晨报助手 | 重新生成晨报
---
- 我 → 晨报助手：今天的晨报没来，先别重试，告诉我卡在哪
- 晨报助手 → 我：凌晨的运行需要一次审批，没人处理，已过期
- 我 → 晨报助手：这类读取动作以后直接放行，现在重做一次
- 晨报助手 → 我：晨报已生成，以后需要你处理时会发通知
:::

后来他让晨报助手每周日晚上做一次自检：列出这一周所有过期的审批和失败的运行，再决定哪些规则要调整。

::: prompt
你是这个“晨报助手”。以后遇到问题请按下面规则：
1. 运行失败或审批过期时，先告诉我原因，不要自己反复重试；
2. 需要我登录、审批或接管时，说清是哪个网站、哪一步；
3. 永远不要自己恢复或重置电脑，需要时先征求我同意；
4. 每周日晚上汇总一次本周的失败和过期记录。
先复述规则。
:::

## 社区玩法精选 {#community}

本期整理了几类常见、好上手的用法，供大家参考。都是通用思路，具体内容换成你自己的。

### 订阅状态页 {#c1}

在 status.cursor.com 订阅更新，服务出问题时先收到通知，就不会把服务故障当成自己的问题去折腾。

### 更新前盘点 {#c2}

每次更新电脑前，让 Bot 列一份装过的应用和软件包清单，更新完照着重装。

### 一句话自检 {#c3}

把技巧一的提示词存成片段，遇到 Bot 半天没反应时直接发，先让它说清卡在哪。

### 审批不过夜 {#c4}

给跑 Routine 的 Bot 打开通知，再把信得过的只读动作设成自动放行，夜里的任务就不会卡在过期的审批上。

### 报错模板 {#c5}

准备一份联系支持用的模板：版本信息、request ID、时间和时区、已试过的步骤，遇到问题时照着填。

## 本期小练习 {#exercise}

花 10 分钟，在出问题之前先把准备做好。

::: steps
- 收藏状态页 | 打开 status.cursor.com，找到 Grok Bot 这一行并订阅更新。
- 复制一次版本信息 | 在账号菜单里选 Support → About，点 Copy version info，看看里面有什么。
- 查一遍隐藏的 Bot | 打开侧边栏的 Hidden Bots，确认没有误藏的 Bot。
- 检查一个 Routine | 用技巧四的清单核对一个 Routine，并给它的 Bot 打开 Notifications。
