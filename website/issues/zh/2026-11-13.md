## 本期导读 {#intro}

用 Bot 干活，最常见的两头是“资料怎么给它”和“成果怎么拿回来”。资料给得不清楚，它就得猜；成果要得不具体，拿回来的东西就不好检查、也不好转交。

官方文档专门有一页“Files and results”讲这件事：附件怎么发、成果怎么要、页面（Pages）怎么看和分享、Library 里怎么找回旧成果。本期按这个顺序，整理成 5 条能直接上手的技巧。

::: callout 一句话记住本期
发资料时说清“每个文件是什么、怎么用”，要成果时说清“做成什么、怎么验收”；做好的页面默认只有你能看，分享前先想清楚给谁看。
:::

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接用。

### 技巧一：附件要带“说明书” {#tip1}

点附件按钮或直接把文件拖进输入框，也可以粘贴图片和链接。常见的图片、音视频、PDF、Word、Excel、PowerPoint、CSV、JSON 等格式都支持。桌面端的限制如下：

| 项目 | 限制 |
| --- | --- |
| 每条消息的附件数 | 20 个 |
| 图片 | 单个 25 MB，每条合计 200 MB |
| 文档、音频及其他文件 | 单个 250 MB |
| 视频 | 单个 1 GB |

超限的文件会被提示过大并留下不发，剩下的另起一条消息再发即可。加密、损坏或格式少见的文件可能读不出来，可以先导出成 PDF、CSV、纯文本或图片。手机上也能从别的应用通过系统分享菜单直接发给某个 Bot。

比文件本身更重要的，是告诉 Bot 每个文件是什么、该怎么用：

::: prompt
我发了两个附件：
1. PDF 是我们已经签好的 [报销制度]；
2. 表格是 [本月的报销明细]。
请对照制度逐条核对明细，每一条异常都注明对应的制度条款，最后返回一个新的表格和一段简短总结。不要修改原始文件。
:::

### 技巧二：要成果，先说清“做成什么、怎么验收” {#tip2}

官方建议在提需求时就指定交付形式和验收标准，例如：

::: props
- 文档: 带小标题和来源链接
- 表格: 列名和公式事先定好
- 幻灯片: 附演讲者备注
- 文件夹: 装好截图和日志
- 消息草稿: 只起草、不发送
- 建议: 先给一句结论，再附依据
:::

对重要的工作，再让 Bot 把内容分成五块写：来源系统里查到的事实、假设或推断、已经完成的动作、等你批准的动作、还没解决的问题。成果出来后要改，就让它改**原来那一份**，不要每次都另起一份新的。

::: prompt
请帮我整理 [某个项目] 本周的进展，做成一份文档：
1. 每个结论后面附上来源链接；
2. 分五部分写：查到的事实、推断、已完成的事、等我批准的事、未解决的问题；
3. 最后单独列出你没能核实的内容。
之后我提修改意见时，请直接改这一份，不要另建新文件。
:::

### 技巧三：让 Bot 做一个页面（Pages） {#tip3}

页面是 Bot 为你做的可阅读成果，比如报告、备忘、看板、追踪表或讲解，可以放文字、表格、图表，还能带筛选和开关。直接在对话里说清页面的用途和内容即可，Bot 做好后会在对话里发一张带标题和 **Open** 的卡片。

::: steps
- 打开 | 桌面端点卡片，页面铺满窗口，旁边保留一个小的对话面板，边看边聊。
- 修改 | 在页面旁标着 **Message about** 加页面标题的对话框里提要求，Bot 会改同一个页面；页面上的筛选和开关只改变你看到的内容，不会保存。
- 改名 | 点击自己做的页面顶部的标题，输入新名字后按 Enter；按 Escape 保留原名。
- 更新提示 | Bot 更新页面后，对话里旧的卡片会显示 **Updated below**，点它打开最新版。
:::

Pages 正在逐步推出，Enterprise 团队暂不可用；看不到时，先把桌面端更新到 0.60.0 及以上、手机端更新到 1.14.0 及以上。你也可以让 Routine 定时创建或更新页面。

::: prompt
请做一个页面，帮我对比 [这三份报价]：
1. 用表格列出价格、交付周期、售后条款；
2. 加一个筛选，可以只看满足 [预算上限] 的方案；
3. 页面最后给一段简短建议，并注明依据。
做好后发卡片给我，先保持只有我能看。
:::

### 技巧四：分享页面前，先选对“谁能看” {#tip4}

新页面默认只有你能看。在桌面端打开页面点顶部的 **Share**（或在 Library 里从页面菜单选 **Share…**），就能修改可见范围：

| 选项 | 谁能打开 |
| --- | --- |
| People you invite | 你和你添加的队友或群组，个人账号下显示为 Only you |
| 你的团队名 | 你所在 Cursor 团队的所有人 |
| Anyone with the link | 任何人，无需登录 |

被分享的人都能阅读页面、使用上面的控件，但只有 Bot 能修改页面。选“任何拿到链接的人”时，页面会有一个 `pages.grok.bot` 下的固定地址，任何人拿到都能直接打开，所以**只在页面不含任何隐私时这样分享**；Enterprise 团队关闭了公开分享。想收回，就再打开 Share 选更小的范围；所有分享过的页面也可以在 Cursor 后台的 Grok Bot Pages 里统一查看、改可见范围或删除，删除后拿着链接的人也打不开了。

::: prompt
我准备把 [某个页面] 分享给团队之外的合作方。分享前请帮我检查：
1. 页面里有没有姓名、邮箱、电话、金额、内部链接等不该外传的内容，逐条列出；
2. 如果有，先在同一个页面里改掉或删掉，改完告诉我改了什么；
3. 先不要改分享设置，我确认后自己去改。
:::

### 技巧五：用 Library 找回旧成果 {#tip5}

每个 Bot 都有一个 **Library**：点对话顶部 Bot 的名字打开详情，进入 Library 标签。这里按 **Today**、**This week**、**Older** 列出它做的页面、文件和应用，以及它在对话里发过的图片、视频和链接；你自己上传的东西不在里面。

::: props
- 快速搜索: 桌面端按 Cmd/Ctrl+K，输入页面标题直接找
- 置顶: 在条目的更多菜单里选 Pin，常用的放到最上面的 Pinned
- 按类型看: 桌面端可选 Pages、Media、Links、Files、Apps、Pinned 只看某一类
- 分享标记: 已分享给团队或任何人的页面，所在行会有标记
:::

另外，连接了 Google Drive、OneDrive、SharePoint、Gmail 或 Outlook 后，Bot 可以直接把成果存到网盘或附到邮件草稿里。注意：存到 Google Drive 总会新建文件，即使已有同名文件；OneDrive 和 SharePoint 遇到同名会拒绝，除非你明确让它覆盖。

::: prompt
请帮我盘点一下你的 Library，只汇报、不要改动：
1. 列出最近一周你做的页面和文件，每个附一句用途说明；
2. 标出哪些已经分享给了别人；
3. 建议我置顶哪三个最常用的。
:::

## 几个必须知道的边界 {#limits}

::: steps
- 附件有上限 | 桌面端每条消息最多 20 个附件，超限的文件会被留下不发。
- Pages 未全面开放 | 正在逐步推出，Enterprise 团队暂不可用。
- 公开链接要谨慎 | “任何拿到链接的人”无需登录即可打开，只适合不含隐私的页面。
- 页面只能由 Bot 修改 | 页面上的筛选和开关不会保存，要改内容就请 Bot 改。
- 图片和视频只按需生成 | 图表和表格不用图片生成，请让 Bot 做成页面；视频为 1 到 15 秒，默认 6 秒、480p，可要求 720p。
- 截图不是唯一证据 | 变化快的数据，尽量同时保留来源链接或导出文件。
:::

## 实战案例：虚构的“周报员”怎么交付一份可分享的周报 {#case}

延续前几期的虚构阵容（并非任何人的真实配置）：一位运营负责人每周五要给团队一份数据周报。以前她自己从几张表里复制数字、做图、写结论，现在交给 Bot“周报员”。

| 环节 | 做法 | 注意点 |
| --- | --- | --- |
| 给资料 | 发两份导出的表格，说明各自是什么 | 不让它改原文件 |
| 要成果 | 要一个带图表和筛选的页面 | 结论附依据，未核实的单列 |
| 改稿 | 在页面旁的对话框里提修改 | 改同一个页面，不另建 |
| 分享 | 只分享给自己的团队 | 不用公开链接 |
| 归档 | 在 Library 里置顶这份周报 | 下周让它更新同一页 |

### 亮点：一个页面，每周更新，团队随时能看 {#case-flow}

她只需要提供资料、看一眼结果、点一次分享。

::: flow
- 我 | 发表格并说明用途 | person
- 周报员 | 核对数据并做页面
- 周报员 | 发来页面卡片
- 我 | 提修改意见并分享给团队 | person
- 团队 | 打开页面查看与筛选 | person
---
- 我 → 周报员：两份表格，一份是注册，一份是转化
- 周报员 → 我：页面已做好，有两处数据我没法核实
- 我 → 周报员：把那两处标出来，再加一个按渠道的筛选
- 周报员 → 我：已在同一页面更新
- 我 → 团队：周报页面已分享给大家
:::

后来她让周报员每周五定时更新同一个页面，团队成员拿到的永远是同一个链接、最新的数据。

::: prompt
你是这个“周报员”。以后我发周报数据给你时，请按下面规则处理：
1. 先说明你读到了哪些文件、各自是什么；
2. 成果做成一个页面，包含关键指标、图表和按渠道的筛选；
3. 每个结论附依据，核实不了的单独列出；
4. 每周更新同一个页面，不要另建；不要修改分享设置。
先复述规则。
:::

## 社区玩法精选 {#community}

本期整理了几类常见、好上手的用法，供大家参考。都是通用思路，具体内容换成你自己的。

### 一张截图就能开工 {#c1}

把报错截图、白板照片或纸质单据拍下来直接发给 Bot，并说清要它做什么，比打字描述快得多。

### 报价对比页 {#c2}

把几份报价一起发过去，让它做成带表格和建议的页面，开会时直接打开讲。

### 活的追踪表 {#c3}

让 Bot 做一个发布追踪页，列出任务、负责人和状态，之后每次进展都让它更新同一页。

### 成果直存网盘 {#c4}

连接网盘后，让 Bot 把做好的文件直接存到指定文件夹，省去下载再上传。

### 配图和短片 {#c5}

需要一张示意图或一段几秒的短片时，描述画面、风格和比例，让 Bot 生成；需要精确文字或品牌素材的，还是交给设计工具。

## 本期小练习 {#exercise}

花 15 分钟，用一份小资料完整走一遍“发资料、拿页面、改页面、找回来”。

::: steps
- 准备资料 | 找一份不含隐私的小表格，比如一周的开支或阅读记录。
- 带说明发送 | 把表格发给 Bot，说清它是什么、要做成什么样的页面。
- 改同一页 | 打开页面，在旁边的对话框里提一条修改意见，确认它改的是同一个页面。
- 检查分享 | 打开 Share，确认页面当前只有你能看。
- 找回来 | 关掉页面，到 Bot 的 Library 里找到它并置顶。
:::
