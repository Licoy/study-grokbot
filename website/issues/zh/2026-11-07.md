## 本期导读 {#intro}

第 1 期讲过怎么创建和管理多个 Bot。本期往下走一层：几个人工智能队友怎么一起干活——什么时候开群聊、开场怎么指定负责人、Bot 之间怎么异步交接、附件怎么传，以及共用电脑与群聊记忆的边界。

Grok Bot 可以单独干活，也可以和其它 Bot 协作。群聊适合「共享结果 + 可见交接」；Bot 到 Bot 的交接适合「源系统归 A、交付物归 B」这类分工。用对场景，协作清晰；用错场景，就会重复劳动、消息嘈杂。

::: callout 一句话记住本期
共享结果开群聊；每阶段只留一个负责人；交接异步可见；图发给需要看的那个 Bot；共用电脑与群聊发言都当公开边界。
:::

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接发给你的 Bot。

### 技巧一：先分清群聊和 Bot 交接 {#tip1}

官方文档把两种协作方式分得很清楚。

适合开群聊的情况：

::: props
- 共享结果: 几个 Bot 要共同完成一件事
- 可见交接: 你希望看到谁接了、交了什么
- 规模: 新建聊天时选 2–6 个 Bot
:::

适合用 Bot 之间异步交接的情况：

::: props
- 源与交付分属不同 Bot: 一个管源系统，一个管最终产出
- 长任务继续跑: 不想由你逐步协调每一步
- 交接可见: 你仍能在对话里看到这次交接
:::

Primary Bot 是你的主联络人：它会主动跟进，也能把活转给更专长的 Bot。Shared Bot 不能当 Primary。日常可以把任务先发给 Primary，再由它按分工交接。

::: prompt
请帮我判断下面这个任务该开群聊，还是用 Bot 之间的异步交接：
目标：[一句话结果]
参与角色：[2–6 个角色名]
是否需要我看到每步交接：[是/否]
源系统由谁负责：[Bot 名]
最终交付由谁负责：[Bot 名]
用三句话给出建议，并说明理由。先不要创建任何群聊或发起交接。
:::

### 技巧二：开场就指定每阶段唯一负责人 {#tip2}

建好群之后，写清最终结果，并用 @ 给每个阶段指定唯一负责人。平时正常写，让 Bot 自己决定谁来回；输入 @ 可以把话交给某一个队友；把 @everyone 留给面向全组的更新。

官方推荐的开场写法很直接：

::: prompt
@资料研究员 搜集原始材料，每条主张都附上链接。@撰稿人 把发现写成发布草稿。@审稿人 对照来源核对草稿，只列出阻塞问题。先不要发布任何东西。
:::

「每阶段一个负责人」是协作里最重要的习惯之一。开场就写清楚，后面才不容易抢活、漏活。

::: prompt
我们开一个群聊来完成：[最终结果]。
参与：@资料研究员 @撰稿人 @审稿人 @规划师
请按阶段认领唯一负责人（每阶段只一人）：
1. 搜集与核对来源；
2. 写成草稿；
3. 对照来源列出阻塞问题；
4. 汇总进度给我。
开场确认后开始第 1 阶段。未获我明确批准前，不要对外发送或发布任何内容。
:::

### 技巧三：理解交接怎么走，以及 Slack 里的规则 {#tip3}

Bot 可以给另一个 Bot 发异步消息：对方醒来处理，之后可以再回复；你会在对话里看到这次交接。适合「一个 Bot 拥有源系统、另一个拥有交付物」，或长任务不该由你逐步协调的场景。

关键约束：

::: props
- 每阶段一个负责人: 并行向多个 Bot 分发同一阶段，容易重复劳动、更新嘈杂
- 应用 / 你自己的 Slack 私信: 任意 Bot 都能交接工作
- Slack 频道线程: 只有 Shared Bot 能代表提到它的那个人交接
- 交接需要代表某个人: 交接发生时，Bot 是在代表某个人行动
:::

你的私信优先于后台工作。需要立刻停下时说「现在停下」——它会马上结束当前工作，但不会撤销已经完成的动作。

::: prompt
请按下面规则做一次交接（先说明你会交给谁、交什么，再执行）：
1. 当前阶段负责人：[当前 Bot]；
2. 下一阶段负责人：[下一个 Bot]；
3. 交接内容：[材料摘要 / 待办清单 / 阻塞项]；
4. 明确不要并行分发给其它 Bot。
交接后在本对话里回我一句确认。未获批准前不要发布或对外发送。
:::

### 技巧四：群里能带附件；Bot 到群是纯文字 {#tip4}

你在群聊里发的消息可以带附件。但 Bot 发到群聊的交接消息是纯文字——当某个队友必须查看图片时，应把图直接发给那个 Bot，而不是指望它从群聊交接里「带图过去」。

实用分法：

::: props
- 你 → 群: 可以附上截图、表格、文档
- Bot → 群: 交接消息是纯文字摘要与链接
- Bot → 指定 Bot: 需要对方看图时，直接把图发给它
:::

写交接摘要时，把结论、链接、阻塞项写清楚；真正要「看见」的素材，留给点对点发送。

::: prompt
请准备一条发给群聊的交接摘要（纯文字，不要试图在群交接里夹带图片）：
1. 本阶段完成了什么；
2. 关键链接与出处；
3. 下一阶段负责人与待办；
4. 阻塞问题（如有）。
若有必须给下一负责人查看的截图，请先列清单，等我确认后再直接发给那个 Bot。
:::

### 技巧五：共用电脑与群聊记忆的边界 {#tip5}

所有你的 Bot 共用一台电脑：文件和浏览器会话是共享的。每个 Bot 有自己的屏幕（同一时间一个屏幕上一个电脑使用任务），但屏幕不是安全边界。别把「不该被你其它 Bot 使用」的凭证放在这台电脑上。

群聊里的记忆规则同样要记牢：

::: steps
- 私聊内容可用 | 群聊里，你的 Bot 可以用你在私聊告诉它的内容。
- 记忆彼此不共享 | 每个 Bot 保留自己的记忆，不会在群里的其它 Bot 之间共享。
- 说出口就可见 | 群成员能看到你的 Bot 说了什么。
- 不想公开就明说 | 有些事必须留在私聊，要明确告诉它。
:::

你还可以 @ 提及某个 Bot、某个群、某条 Routine 或某个应用，把注意力精确转到该对象。

::: prompt
请确认并遵守下面这些协作边界：
1. 不要把 [敏感凭证类别] 存到共用电脑上；
2. 群聊里只分享可公开的摘要，下列内容不得复述：[禁止项]；
3. 需要其它 Bot 看图时，直接发给对方，不走群聊纯文字交接夹带；
4. 每个阶段只保留一个负责人，不要并行分发同一任务。
用四句话复述你将如何遵守。
:::

## 几个必须知道的边界 {#limits}

::: steps
- 群聊规模 | 新建聊天时选 2–6 个 Bot；不是无限人同时进场。
- @everyone 慎用 | 留给面向全组的更新；日常交给具体负责人。
- 并行交接易乱 | 同一阶段只留一个负责人，避免重复劳动和嘈杂更新。
- Slack 频道限制 | 频道线程里只有 Shared Bot 能代表提到它的人交接。
- Bot → 群纯文字 | 需要看图时，把图直接发给那个 Bot。
- 屏幕不是隔离 | 共用电脑上的凭证，你的其它 Bot 也可能用到。
- 「现在停下」不撤销 | 立刻结束当前工作，但不撤回已完成动作。
:::

## 实战案例：通讯小队的一期联合作战 {#case}

延续前几期的虚构阵容（并非任何人的真实配置）：资料研究员、撰稿人、审稿人、规划师、构建师。这一期他们要共同产出一封发布通讯——共享结果、交接可见，于是开了群聊，而不是各自私信来回传。

| 阶段 | 唯一负责人 | 输入 | 输出 | 不做什么 |
| --- | --- | --- | --- | --- |
| 搜集 | 资料研究员 | 选题与范围 | 带来源链接的材料包 | 不写正文、不发布 |
| 起草 | 撰稿人 | 材料包 | 发布草稿 | 不改来源结论 |
| 核对 | 审稿人 | 草稿 + 来源 | 仅阻塞问题清单 | 不直接改稿、不发布 |
| 统筹 | 规划师 | 各阶段回传 | 进度与下一步 | 不并行把同一阶段分给多人 |
| 版式（可选） | 构建师 | 定稿结构 | 页面/模板检查项 | 不碰凭证、不自动上线 |

### 亮点：开场认领 → 异步交接 → 群里只留摘要 {#case-flow}

他们按「一个结果、一条主线、每阶段一人」推进；需要看截图时，由当前负责人把图直接发给下一个 Bot。

::: flow
- 我 | 开群聊，用 @ 指定每阶段负责人 | person
- 资料研究员 | 搜集材料，链接每条主张
- 撰稿人 | 写成发布草稿
- 审稿人 | 对照来源，只列阻塞问题
- 规划师 | 汇总进度，请示是否进入下一轮
---
- 我 → 群：开场认领与「先不发布」
- 资料研究员 → 撰稿人：材料包交接（群内纯文字摘要）
- 撰稿人 → 审稿人：草稿交接
- 审稿人 → 规划师：阻塞清单
- 规划师 → 我：请示是否继续
:::

若某张配图必须给审稿人「看见」，撰稿人会把图直接发给审稿人，同时在群里只留一句纯文字说明。Primary（若由规划师兼任主联络）负责跟进卡点，而不是让所有人同时抢同一阶段。

::: prompt
你是这个团队的规划师。请为「一期通讯」起草群聊开场说明：
1. 最终结果一句话；
2. 用 @ 指定搜集 / 起草 / 核对 / 统筹的唯一负责人；
3. 写明「先不要发布任何东西」；
4. 提醒：群交接纯文字；必须看图时点对点发送。
只给开场文案，不要开始执行。
:::

## 社区玩法精选 {#community}

本期整理了几类常见、好上手的用法，供大家参考。都是通用思路，具体内容换成你自己的。

### 三人最小群 {#c1}

资料、撰稿、审稿各一人，开场三句 @ 认领。比五人同时进场更容易看清交接。

### 开场模板存成片段 {#c2}

把「结果 + 每阶段负责人 + 先不发布」存成可复制片段，新项目直接改角色名。

### 卡点只问规划师 {#c3}

群成员有疑问先 @ 规划师汇总，避免同一问题被多个 Bot 同时回答。

### 附件分流 {#c4}

你把大附件丢进群；Bot 之间只传摘要与链接；必须看图的步骤走点对点。

### 敏感事提前封口 {#c5}

开群前告诉各 Bot：哪些私聊内容不得在群里复述；群里只留可公开摘要。

## 本期小练习 {#exercise}

花 15 分钟，用虚构或真实任务跑一轮「群聊 + 交接」演练。

::: steps
- 选场景 | 写清一个共享结果，以及 2–4 个角色；判断该开群聊还是只用异步交接。
- 写开场 | 用 @ 给每阶段指定唯一负责人，并写上「先不要发布任何东西」。
- 演练交接 | 让第 1 阶段负责人把纯文字摘要交给第 2 阶段；若有图，改为直接发给对方。
- 核对边界 | 确认没有把敏感凭证放上共用电脑；不想公开的内容已明确禁止复述。
- 停与复盘 | 需要时说「现在停下」；回顾是否出现并行分发或 @everyone 滥用。
:::
