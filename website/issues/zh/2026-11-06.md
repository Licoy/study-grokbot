## 本期导读 {#intro}

第 1 期技巧三里点到：长期规矩要写进记忆，记忆不是权威数据源。第 5 期又提醒：记忆写入不在 Auto-review 的审查范围内。本期把「记住什么、怎么改、怎么删、跨 Bot 怎么共享」一次讲透。

Grok Bot 的记忆是每个 Bot 自己的长期上下文。它会自己决定什么值得留下，你也可以在聊天里直接纠正或忘掉。用得好，Bot 越用越懂你；不管，过时事实会悄悄影响后续判断。

::: callout 一句话记住本期
重要的说「记住」；过时的当面纠正；登录进 Vault；会变的数字回源头；安全边界别只靠记忆。
:::

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接发给你的 Bot。

### 技巧一：分清记忆和 Vault {#tip1}

官方文档把「该记」和「不该进记忆」分得很清楚。

记忆里通常会留下：

::: props
- 工作方式: 你喜欢怎么协作、输出风格等偏好
- 规矩: 你要求它遵守的规则，例如发邮件前先问你
- 关于你的事实: 姓名、时区等
- 工作日志: 过往合作的日期摘要
:::

这些东西不进记忆，而是进 Vault：

::: props
- 登录: 账号密码
- 卡片: 支付信息
- 联系方式: 地址、电话等
:::

Vault 在设置里单独管理，方便 Bot 帮你登录或结账，又不会把密码写进普通记忆。把密钥、地址随口丢进聊天当「记住」，既不安全，也容易和真正的偏好混在一起。

::: prompt
请确认并记住下面这些长期偏好（不要记任何密码、卡片或电话）：
1. 我的时区是 [时区]；
2. 对外发送任何邮件前都先问我；
3. 回复默认用 [语言/语气]。
记好后，用三句话复述你记住了什么。登录与联系方式我会放在 Vault，不要写进记忆。
:::

### 技巧二：想确保记住，就明确说「记住」 {#tip2}

Bot 自己决定何时值得保存，不会先问你。回复里常会提一句「已记住」，但不一定每次都提。所以真正重要的规矩，最好自己开口确认。

官方例子很直白：「记住我每周五都不在。」

同一 Bot 的所有对话共享它的记忆：在这个聊天里记住的事，换一个对话窗口它仍然知道。每个 Bot 又有自己的记忆；只有姓名、时区等少数事实会在所有 Bot 之间共享——一个学会后，其它 Bot 也会知道。

语音通话里，Bot 可以用更早的通话和近期聊天；挂断之后，你还可以在文字聊天里问刚才通话说了什么。群聊里，Bot 可以用你在私聊告诉它的内容；每个 Bot 的记忆彼此不共享，但群成员能看到你的 Bot 说出口的话。不想出现在群里的事，要明确告诉它。

::: prompt
请记住：[具体事实或规矩]。
这是长期有效的，以后相关任务都要遵守。
记好后告诉我：这条是只存在你自己的记忆里，还是属于所有 Bot 共享的那类事实。
:::

### 技巧三：用聊天查看、纠正、删除 {#tip3}

个人 Bot 没有记忆列表界面。查看、纠正、删除都在聊天里完成：

::: props
- 查看: 「你还记得我什么？」
- 纠正: 「这过时了，我搬到丹佛了。」
- 删除: 「忘掉我在发布团队。」
:::

发现 Bot 还在用过时假设时，直接纠正比开新对话更有效——重置对话只会清历史，记忆还在。

纠正共享事实（姓名、时区等）时：告诉任意一个 Bot 正确版本即可。要彻底删掉共享事实：找当初保存它的那个 Bot，对它说忘掉。

::: prompt
请列出你目前关于我、以及关于你角色的主要记忆（按类别分组：偏好、规矩、事实、近期工作）。
标出你觉得可能已过时的条目。
对下面这些请立刻处理：
1. 纠正：[旧说法] → [新说法]；
2. 忘掉：[不再成立的事实]。
处理完再复述一遍更新后的要点。
:::

### 技巧四：搞清楚重置、隐藏、删除分别动什么 {#tip4}

官方对照表很清楚：

| 操作 | 记忆会怎样 |
| --- | --- |
| 重置对话（Reset conversation） | 保留 |
| 删除 Bot（Delete） | 该 Bot 的记忆删除（含它为其它 Bot 保存的共享事实） |
| 删除账号 | 全部删除 |

消息被自动审查拦住时，通知里有时会提供重置：对话历史重来，但记忆、文件、Routine 和设置都会保留。

侧边栏里「Hide from sidebar」只是收起，记忆还在；「Delete」不可撤销，对话、记忆、Routine、附件都会清掉，包括它替其它 Bot 存下的共享事实。可能还要用这个 Bot 时，先隐藏，别急着删。

个人 Bot 的记忆只属于你。Shared Bot 可以为团队记事并告知你；它不会把你的个人事实存给团队；队友的 Shared Bot 也拿不到你个人 Bot 共享的那些事实。

::: prompt
请帮我做一次记忆体检（只报告，先别删）：
1. 哪些记忆是只属于你的；
2. 哪些可能是所有 Bot 共享的事实；
3. 如果我现在删除你，哪些共享事实可能一起消失。
用清单回答。
:::

### 技巧五：记忆不是权威源，安全边界别只靠它 {#tip5}

官方文档单独强调：记忆不是权威数据源。

::: steps
- 会变的事实留在源系统 | 价格、库存、排期等仍以源头为准，重要决策前让 Bot 重新打开当前数据。
- 过时假设当面纠正 | 发现 Bot 还在用旧地址、旧职位，直接说「这过时了……」。
- 安全边界用规则兜底 | 审批与 Auto-review 自定义规则管动作；记忆写入本身不在自动审查范围内，别指望「记住：发邮件前先问我」就能代替一条「先问我」规则。
- 可从其它助手导入 | 在 Settings → General → Import 下点 Start Import：把提示词复制到另一个助手，把它的回答贴进第二个框，选 Add to Memory；内容会发到你的 primary Bot 并打开该聊天。
:::

第 5 期讲过：自动审查不覆盖记忆写入。所以「记住别乱发」和「发之前先问我」是两层——前者是偏好，后者才是硬闸门。

::: prompt
请区分处理下面两类信息：
1. 可以写进记忆的长期偏好：[偏好列表]；
2. 每次都要重新核对的数据源：[系统/表格/页面]。
对第 2 类，重大结论前必须重新打开源头，不要只靠记忆里的旧数字。
另外确认：对外发送、删除、付款这类动作，仍以我设置的审批规则为准，不以记忆里的一句话代替。
:::

## 几个必须知道的边界 {#limits}

::: steps
- 没有记忆列表页 | 个人 Bot 用聊天管理记忆，没有单独的清单界面可点。
- 保存不一定每次告知 | Bot 常会提一句，但不保证每条保存都出现在回复里。
- 删除 Bot 不可撤销 | 会清掉该 Bot 记忆，以及它为其它 Bot 保存的共享事实；想留记忆就用隐藏。
- 群聊可见发言 | 记忆不在 Bot 之间共享，但你的 Bot 在群里说的话，群成员都能看见。
- 记忆写不进自动审查 | 安全相关的硬性要求，请写成审批 / Auto-review 规则，不要只写进记忆。
:::

## 实战案例：通讯小队的记忆大扫除 {#case}

延续前几期的虚构阵容（并非任何人的真实配置）：资料研究员、撰稿人、审稿人、规划师、构建师。用了几周之后，他们发现有的 Bot 还在用旧的截稿日，有的把临时口吻当成了长期规矩。于是做了一次记忆维护：

| Bot | 该记住的 | 该忘掉 / 纠正的 | 不进记忆的 |
| --- | --- | --- | --- |
| 资料研究员 | 只引用可公开核对的来源；输出带链接 | 上周临时的「今天只查内部文档」 | 付费库账号进 Vault |
| 撰稿人 | 通讯语气、标题字数上限 | 过期的节日专题口吻 | 发布渠道登录进 Vault |
| 审稿人 | 核对清单：事实、链接、敏感词 | 无 | 无 |
| 规划师 | 团队所在时区；发邀请前先问 | 已取消的双周例会 | 会议室门锁密码进 Vault |
| 构建师 | 测试命令与分支命名约定 | 已废弃的旧部署流程 | 部署密钥进 Vault / Secrets |

### 亮点：先盘点，再纠正，最后加闸门 {#case-flow}

他们没有一上来就删除 Bot，而是按「查看 → 纠正 → 确认规矩 → 检查审批规则」走了一遍。

::: flow
- 规划师 | 让每个 Bot 列出主要记忆
- 各 Bot | 纠正过时条目、忘掉临时指令
- 我 | 确认共享事实（时区等）是否正确 | person
- 审批规则 | 核对「先问我」是否仍在，不靠记忆代替
---
- 规划师 → 各 Bot：发起记忆盘点
- 各 Bot → 我：交回清单与拟纠正项
- 我 → 各 Bot：批准纠正 / 删除
- 我 → 审批规则：确认硬闸门仍在
:::

共享时区若写错，告诉任意一个 Bot 改过来即可；若要彻底忘掉某条当初由撰稿人存下的共享事实，则必须对撰稿人说「忘掉……」。

::: prompt
你是这个团队的规划师。请为资料研究员、撰稿人、审稿人、构建师各起草一份「记忆维护清单」：
1. 应长期记住的 3 条；
2. 可能过时、需要我确认的 2 条；
3. 明确不应进记忆、应放 Vault 的 1 类信息。
只给方案，不要修改任何记忆。
:::

## 社区玩法精选 {#community}

本期整理了几类常见、好上手的用法，供大家参考。都是通用思路，具体内容换成你自己的。

### 每周五问一句 {#c1}

固定问：「你还记得我什么？有没有过时的？」比出了错再补救省事。

### 临时任务加保质期 {#c2}

交代临时偏好时写明有效期，例如「只在本周有效，下周请忘掉」。到期主动让它忘掉。

### 新 Bot 开工三句话 {#c3}

创建后立刻：角色是谁、长期规矩、哪些事每次回源头核对。让它复述一遍再开始干活。

### 私聊机密、群聊脱敏 {#c4}

不想出现在群聊的内容，事先明确禁止复述；群里需要协作时，只分享可以公开的摘要。

### 导入后立刻体检 {#c5}

从其它助手 Import 进 primary Bot 之后，马上问它记住了什么，删掉不该留下的条目，再开始日常使用。

## 本期小练习 {#exercise}

花 15 分钟，给你的 Bot 做一次记忆维护。

::: steps
- 盘点 | 对常用 Bot 说：「你还记得我什么？」按偏好、规矩、事实分类看一遍。
- 纠正与删除 | 过时的直接纠正，不再成立的说「忘掉……」。
- 确认共享事实 | 核对姓名、时区等；要彻底删除某条共享事实时，找到当初保存它的那个 Bot。
- 分流敏感信息 | 登录、卡片、地址电话进 Vault，不要留在记忆里。
- 补一条硬闸门 | 打开 Auto-review 自定义规则，确认「对外发送前先问我」仍在——不要只写在记忆里。
:::
