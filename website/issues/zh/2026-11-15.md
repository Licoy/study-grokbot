qa:
  - q: Bot 能看到我存在 Vault 里的密码吗？
    a: 不能。Bot 只知道你存了哪些登录，密码由 Vault 直接填进网页。在 Grok Bot 应用的对话里，Bot 能看到已存卡片的卡号和安全码，用于在你点订单卡上的 Pay 后填进结账页，或在你问起时告诉你。
  - q: 能不能让某张卡或某个登录只给一个 Bot 用？
    a: 不能。Vault 对整个账号生效，存进去的东西账号下每个 Bot 都能用。团队 Bot 用不了你的 Vault，它的登录要由管理者在团队 Bot 的设置里单独添加。
  - q: 我已经在用别的密码管理器，要一条条重新输入吗？
    a: 不用。在桌面端的 Settings → Vault 里选 New item，再选 Import from CSV…，导入从 1Password、Chrome 或 Edge、Safari 或 Apple 密码、Firefox、Bitwarden、LastPass 导出的 CSV。文件只在你电脑上读取、不会上传，大小要在 5 MB 以内；导入完记得删掉这份未加密的导出文件。
  - q: 机密保存后看不到了，是不是被删了？
    a: 不一定。保存的值是只写的：Vault 里密码一直隐藏，卡片只显示后四位，安全密钥卡片保存后也不再显示值。团队 Bot 的 Secrets 里只要名称还在，值就还在。

## 本期导读 {#intro}

前几期在讲云端电脑、记忆和审批时，都顺带提过一句“密码进 Vault，不进聊天”。可 Vault 到底能存什么、Bot 怎么用它、让 Bot 替你买东西时钱是怎么付出去的，一直没有展开讲。

官方文档专门有一页“Vault and secure sign-in”。本期按“存、取、填、藏、付”的顺序，整理成 5 条能直接上手的技巧：把登录和卡片存进 Vault、弄清 Bot 登录的取用顺序、用好安全表单、把 API 密钥放进安全卡片，以及给代付定好规矩。

::: callout 一句话记住本期
密码、验证码、密钥一律不进聊天：登录和卡片存 Vault，临时的值用安全表单，API 密钥用安全密钥卡片；存了卡就等于允许结账时自动付款，想每笔都把关就别存。
:::

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接用。

### 技巧一：把登录、卡片和联系方式存进 Vault {#tip1}

在桌面端或手机上打开 **Settings → Vault**，选 **New item**，再选要存的类型：

::: props
- 登录: 填网站、用户名或邮箱、密码，点 **Save login**；Bot 会用它登录这个网站
- 卡片: 可选 **Scan with camera** 或 **Upload a photo** 从卡面识别，也可以手动输入，点 **Save card**
- 联系方式: 填姓名、地址、电话和邮箱，点 **Save contact info**；用于收货和账单信息
:::

每个条目都可以在 **Hints** 里写一句什么时候用它，比如“公司采购用这张”，Bot 在几个条目之间挑选时会照着做。已经在用别的密码管理器的话，可以在桌面端选 **New item** → **Import from CSV…** 导入导出的 CSV：文件只在本机读取、不会上传，要小于 5 MB，已存在的条目会跳过，缺密码或网站不是 https 的行不会导入。导出文件里的密码是明文，导入完就删掉。

::: prompt
我刚在 Vault 里存了两张卡，请帮我核对一下用法：
1. 列出你能看到的卡片昵称和它们的 Hints，不要念出完整卡号；
2. 告诉我以后哪类购买会用哪张卡；
3. 如果有哪张卡没写 Hints，提醒我补上。
:::

### 技巧二：弄清 Bot 登录网站的顺序 {#tip2}

Bot 要登录一个网站时，按固定顺序取用凭据：

| 顺序 | 来源 | Bot 能不能看到值 |
| --- | --- | --- |
| 1 | Vault 里存的登录 | 看不到，直接填进网页 |
| 2 | 已连接的密码管理器，比如 1Password | 看不到，你在 1Password 里批准后由它填入 |
| 3 | 在对话里弹出安全表单问你 | 看不到，直接填进网页 |

网站发来一次性验证码时，Bot 可以从已连接的 Gmail 或 Outlook，或者它自己的专属邮箱里读取。让 Bot 注册新账号时，如果允许它自己定密码，Vault 会生成密码并保存这个登录，Bot 全程看不到。遇到单点登录、通行密钥、过不去的验证码、要在另一台设备上确认、扫二维码或银行卡验证这类表单做不了的步骤，Bot 会把电脑交给你：点请求上的 **Take over**，只完成这一步，再点 **I'm done** 并让它继续。登录状态会留在电脑上，之后的任务和你的其他 Bot 都能接着用。

::: prompt
接下来请帮我登录 [某个网站] 下载上个月的账单：
1. 先用 Vault 里的登录，没有的话再用安全表单问我，不要让我在聊天里发密码；
2. 遇到二维码或通行密钥这类步骤，告诉我是哪一步，我来接管；
3. 下载完只告诉我文件名和金额，不要改动账户里的任何设置。
:::

### 技巧三：用好安全表单，选对“存”还是“不存” {#tip3}

当网页需要只有你能提供的信息时，Bot 会在对话里弹出 **Secure Form**，每一步一张表单。表单上写明会填到哪个网站，你填的内容直接进网页，Bot 看不到。

::: steps
- 想下次还用 | 勾选 **Securely save to Bot's vault**，这个登录、卡片或联系方式会存进 Vault。
- 只用这一次 | 不勾选，值只在这次对话里使用，之后自动过期。
- 没有复选框的表单 | 会直接存进 Vault，不想存就不要提交。
- 看结果 | 显示 **Filled into the page** 就是已填好；显示 **Could not fill into the page** 多半是网页在填写前变了，值同样没给 Bot 看，Bot 再问时重新提交一张即可。
:::

另外，你在对话里发给 Bot 的姓名、地址、电话或邮箱，任务完成后它会存为联系方式并告诉你存了什么；不想保留就直接跟它说。

::: prompt
以后需要我提供登录或付款信息时，请按这个规矩来：
1. 一律用安全表单，不要让我在聊天里打字；
2. 弹表单前先告诉我这是哪个网站、哪一步、为什么需要；
3. 默认我只用这一次，除非我说“存起来”。
请先复述这个规矩。
:::

### 技巧四：API 密钥放进安全密钥卡片 {#tip4}

API 密钥这类既不是登录也不是卡片的机密，等 Bot 弹出 **secure secret card** 时再填：输入框是遮住的，点 **Save securely** 后卡片显示 **Saved**，值不会写进聊天，也不会给 Bot 看。官方明确提醒：不要把密码、一次性验证码或 API 密钥粘贴进普通聊天、Shell 命令或电脑上的文件，演示教学时也不要输入机密。

保存的值是只写的，看不到不等于丢了：

::: props
- Vault: 密码一直隐藏，卡片只显示后四位
- 安全密钥卡片: 保存后不再显示值，底部写着 **Stored securely, never shown to your Bot**
- 团队 Bot 的 Secrets: 只列名称和描述，在 Shell 里也看不到值；名称还在，值就还在
- 改值: 点 **Replace** 粘贴新值，再点 **Replace value**，旧值读不回来
:::

还要注意：云端电脑的恢复、重置和更新会清掉装过的应用和软件包，你写进文件、Shell 配置或某个工具里的机密可能跟着消失；用安全卡片、Secrets 或 Vault 存的不受影响。

::: prompt
我需要你调用 [某个服务] 的 API：
1. 先弹出安全密钥卡片让我保存密钥，不要让我在聊天里发；
2. 任何时候都不要把密钥打印出来，也不要写进文件；
3. 先只做一次只读请求，告诉我结果是否正常。
:::

### 技巧五：给代付定好规矩 {#tip5}

存进 Vault 的卡在结账时会自动填入，没有“每次使用都要你批准”的设置。想每一笔都亲自把关，就别存卡：结账时 Bot 用安全表单要卡，不勾选保存；已经存了的，在 **Settings → Vault** 里选中它点 **Remove**。

::: props
- 订单卡: Bot 通过订单卡替你买东西时，用 Vault 里的卡付款，你点 **Pay** 批准；没存卡的话，Bot 会先用安全表单要卡；不保存的卡没有订单卡，Bot 会在对话里请你批准确切的总金额
- 批量付款: 一张订单卡最多可涵盖 500 笔卡片付款，一次批准在 24 小时内有效，遇到卡被拒就停下并告诉你哪些成功、哪些失败
- 钱包: **Payment accounts** 里可以连接 Link、X Money、Shop Pay 等钱包，**Default payment method** 决定优先用哪种方式付款；钱包每笔付款都要一张订单卡
- Link 一次性卡: 连接 Link 后，Bot 可以请你批准一张单次购买用的一次性卡，请求里列出商家、商品和总价；你可以点显示金额的 **Pay** 批准、点 **Pay another way** 跳过这张卡，或点 **Deny** 拒绝；拒绝或过期都不会扣款
:::

::: prompt
以后凡是涉及花钱的事，请按下面规则：
1. 下单前先把商家、商品、数量和总价列给我，等我回复“确认”；
2. 总价超过 [100 元] 的，一律不要用已存的卡，改用安全表单让我当场填；
3. 付款完成后，告诉我付了多少、用的是哪张卡的后四位。
请先复述规则。
:::

## 几个必须知道的边界 {#limits}

::: steps
- 版本要求 | Vault 需要 Grok Bot 0.75.2 及以上。
- 整个账号共用 | 存进 Vault 的东西账号下每个 Bot 都能用，不能限定给某一个 Bot。
- 团队 Bot 用不了你的 Vault | 团队 Bot 的登录由管理者在它的设置里单独添加，密钥放进它的 Secrets，团队里能和它聊天的人都会用到。
- 有些只能在设置里改 | 密码、用户名和网站只能在 Settings → Vault 里改，登录和卡片也只能在那里删除；手机上暂时不能编辑已存的卡。
- 存卡即自动填 | 没有“每次使用都要批准”的开关，想每笔把关就别存卡。
- 机密不进聊天 | 密码、验证码和密钥不要贴进聊天、Shell 命令或文件，演示教学时也不要输入。
:::

## 实战案例：虚构的“采购助手”怎么帮一家小工作室 {#case}

延续前几期的虚构阵容（并非任何人的真实配置）：一家五个人的设计工作室，由一位合伙人负责日常采购。她配了一个 Bot“采购助手”，帮她订耗材、续订软件、整理发票。

| 环节 | 做法 | 注意点 |
| --- | --- | --- |
| 准备 | 在 Vault 里存公司卡和收货地址，Hints 写“工作室采购用” | 个人卡不存，避免混用 |
| 登录 | 供应商网站的登录从旧密码管理器导入 | 导入完删掉 CSV |
| 下单 | 采购助手比价后发订单卡 | 核对商家和总价再点 Pay |
| 大额 | 超过预算的采购改用安全表单当场填卡 | 不勾选保存 |
| 对账 | 每周把订单和发票整理成表 | 只列卡号后四位 |

### 亮点：一张订单卡，补齐一周的耗材 {#case-flow}

周五下午，她只需要点一次 Pay，下周要用的打印纸和墨盒就订好了。

::: flow
- 我 | 交代本周要补的耗材 | person
- 采购助手 | 比价并发出订单卡
- 我 | 核对后点 Pay | person
- 采购助手 | 下单并整理发票
- 供应商 | 发货 | person
---
- 我 → 采购助手：打印纸和黑色墨盒快用完了，补一周的量
- 采购助手 → 我：比了三家，这家最便宜，订单卡已发出
- 我 → 采购助手：已批准
- 采购助手 → 供应商：提交订单，用工作室的收货地址
- 采购助手 → 我：已下单，发票已存进本周的对账表
:::

后来她让采购助手每月月底把软件订阅列一遍，标出快到期的，再决定续不续。

::: prompt
你是这个“采购助手”。处理采购时请按下面规则：
1. 只用 Hints 写着“工作室采购用”的卡和地址；
2. 每笔下单前先发订单卡，列清商家、商品和总价；
3. 需要我登录或验证的步骤，说清是哪个网站、哪一步；
4. 对账表里卡号只写后四位，不记录任何密码或验证码。
先复述规则。
:::

## 社区玩法精选 {#community}

本期整理了几类常见、好上手的用法，供大家参考。都是通用思路，具体内容换成你自己的。

### 一次性搬家 {#c1}

从旧的密码管理器导出 CSV，在桌面端导入 Vault，再让 Bot 列出它能用的登录站点，看看有没有过期不用的，顺手删掉。

### 拍卡即存 {#c2}

在对话里发一张银行卡照片时，Grok Bot 会提供 **Save to Vault**，以后 Bot 就能用这张卡付款；不想自动付款的卡就别存。

### 一句话退订 {#c3}

让 Bot 登录某个订阅网站、找到退订入口，把步骤和截图发给你确认后再点退订。

### 机密体检 {#c4}

让 Bot 检查最近的对话和电脑上的文件里有没有误贴的密钥，有的话提醒你去对应服务更换，并改用安全密钥卡片保存。

### 预算闸门 {#c5}

给 Bot 定一条金额上限：低于上限用已存的卡走订单卡，高于上限一律用安全表单当场填卡。
