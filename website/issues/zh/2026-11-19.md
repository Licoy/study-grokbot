## 本期导读 {#intro}

前面几期我们讲过怎么自己建 Bot、怎么把 Bot 分享成模板。但很多时候，你想要的那个 Bot 别人已经做好了：每天盯着网上有没有人提到你的品牌、帮你检查一份融资演示稿、把会议笔记做成回顾幻灯片……

官方的 Bot 市场（Marketplace）就是放这些现成 Bot 的地方。本期把它拆成 5 条技巧：去哪找、怎么看详情页、怎么导入、怎么改成自己的版本，以及不合适时怎么收拾干净。

::: callout 一句话记住本期
先读详情页再导入，导入后是你自己的副本；先回答它的问题、看清它带来的 Routine，发送和发布照样留在审批之后。
:::

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接用。

### 技巧一：知道市场在哪，按分类找 {#tip1}

市场的网址是 [x.ai/bot/marketplace](https://x.ai/bot/marketplace)。在 GrokBot 应用里，打开侧边栏的 **Connect apps**，选 **Bot templates**，也会在浏览器里打开它。

市场按岗位分了类，最上面还有精选（Featured）和官方团队出品（From Grok Bot Team）：

::: props
- 工程: 调研核查、上线前验收、把 API 包装成插件等
- 销售: 筛选潜在客户、会后跟进、给销售通话打分
- 营销: 搜索与 AI 答案的内容选题、长视频剪短片、改写文案
- 设计: 设计评审、Figma 规格、给图片写替代文本
- 个人: 家务提醒、植物养护记录、头像生成
- 招聘与人事、产品、运营: 安排面试、产品想法压力测试、办公事务等
:::

找不到合适的，可以先问问你的主 Bot：把需求讲清楚，让它帮你在市场里挑几个候选。

::: prompt
我想找一个现成的 Bot 来做 [一件事，比如每周盯一次竞争对手的动态]。
请去 GrokBot 的 Bot 市场看看，挑出两三个最接近的，告诉我：
1. 它们各自只负责什么；
2. 需要连哪些应用；
3. 会不会自动发送或发布内容。
先只给我对比，不要导入任何 Bot。
:::

### 技巧二：导入前，把详情页读一遍 {#tip2}

点开任意一个 Bot，详情页会写明作者、一句话介绍，并列出四类内容：

| 详情页里的项目 | 含义 |
| --- | --- |
| memories | 它已经知道的事实 |
| skills | 它能执行的技能（做事步骤） |
| routines | 会自己定时运行的任务 |
| integrations | 它会用到的应用 |

下面还有它的完整说明。好的市场 Bot 通常会写清三件事：它只干哪一件事、明确不做什么、什么时候保持安静。比如 [Overheard](https://x.ai/bot/marketplace/bots/overheard) 的说明里写着：只找别人对你名字、品牌和网址的提及，没有值得报告的就不打扰你，也不会替你发帖。

::: prompt
这是我想导入的一个 Bot 的详情页内容：[粘贴详情页文字]
请帮我检查：
1. 它会用到哪些应用和权限；
2. 它带了哪些 Routine，多久运行一次；
3. 说明里有没有自动发送、发布或付款的动作；
用三五句话告诉我值不值得导入。
:::

### 技巧三：Import Bot 得到的是你自己的副本 {#tip3}

在详情页选 **Import Bot**，就会在你的账号里建一份这个 Bot 的副本。官方文档说明了几点：

::: steps
- 只拿到配置 | 导入的是 Bot 的设定，比如身份、说明、技能和 Routine；作者的电脑、登录状态和聊天记录都不会给你。
- 不是官方出品 | 市场和模板里的 Bot 由其他用户制作，不是 GrokBot 官方出品；导入时会接受第三方 Bot 条款。
- 团队可能有限制 | 在 Teams 和 Enterprise 方案里，管理员可以控制成员能否公开发布模板。
:::

别人私下发给你的模板链接也是同样的道理：打开预览，选 **Add to Grok Bot**，同样是你自己的一份副本。分享模板的做法见[第 9 期](/zh/issues/2026-11-09/)。

::: prompt
我刚从市场导入了 [Bot 名字]。在开始干活前，请先告诉我：
1. 你的职责是什么，明确不做哪些事；
2. 你带来了哪些技能和 Routine，Routine 现在有没有启用；
3. 你需要我连接哪些应用。
先不要运行任何 Routine。
:::

### 技巧四：先回答开场问题，再改成你自己的版本 {#tip4}

很多市场 Bot 第一次运行时会先问你几个问题。比如 Overheard 会先问你要盯哪些名字、品牌和网址，再建每日提醒的 Routine；它的说明里写明，这个 Routine 建好时先不启用，会问你一次要不要打开。

回答完之后，就可以按自己的习惯改造它：

::: steps
- 讲清你的规则 | 时区、语言、发结果的时间、哪些事必须先问你，在聊天里讲清，并让它记住。
- 看清 Routine | 确认每个 Routine 的时间和触发条件，不需要的就让它关掉。
- 只连需要的应用 | 它列出的应用不一定都要连，先连最少的，跑通后再加。
- 跑一次再放手 | 手动让它完整做一次，结果满意了再让 Routine 自动运行。
:::

记忆和 Routine 的维护方法，见[第 6 期](/zh/issues/2026-11-06/)和[第 2 期](/zh/issues/2026-11-02/)。

::: prompt
请按下面的规则调整你自己：
1. 我的时区是 [时区]，结果统一用 [语言] 写；
2. 每个工作日 [上午九点] 把结果发给我，没有值得报告的就不用发；
3. 任何发送、发布或删除动作都先问我。
把这些记住，然后列出你现在所有的 Routine 和它们的时间。
:::

### 技巧五：不合适就隐藏或删除，并清理共用电脑 {#tip5}

导入的 Bot 用了一阵发现不合适，有两种收拾方法：

| 做法 | 结果 | 适合 |
| --- | --- | --- |
| 从侧边栏隐藏（Hide from sidebar） | 从列表里移走，工作和历史都保留，Routine 也照常运行；可以在侧边栏底部的 Hidden Bots 里恢复 | 以后可能还要用 |
| 侧边栏右键 → Delete | 删除它的资料、对话、记忆、Routine 和附件，无法恢复 | 确定不要了 |

隐藏不等于停用。想让它彻底安静，先让它关掉自己的 Routine，再隐藏。

还要注意：你的所有 Bot 共用一台云端电脑，文件和登录状态不按 Bot 隔离。删除 Bot 之后，它在电脑上留下的文件和登录状态还在，需要另外清理。

::: prompt
我打算删除 [Bot 名字]。删除前请帮我：
1. 列出它在共用电脑上建过的文件和文件夹；
2. 列出它登录过的网站；
3. 说明它有没有替其他 Bot 保存过共享的事实。
先只列清单，不要删除任何东西，等我确认。
:::

## 几个必须知道的边界 {#limits}

::: steps
- 隐藏不等于停用 | 隐藏的 Bot 仍然在运行它的 Routine，想停就先关掉 Routine。
- 别人的作品要审一遍 | 市场 Bot 由其他用户制作，说明写得再好，第一次运行也要看着它做。
- 审批照常生效 | 导入的 Bot 和你自己建的一样，风险操作前会先问你；发送、发布和付款仍留在审批之后。
- 密钥不进聊天 | 它要你登录或填 API 密钥时，走 Vault、安全表单或安全密钥卡片，不要直接贴进聊天。
- 电脑是共用的 | 导入的 Bot 也能用到共用电脑上的文件和登录状态，导入前想清楚它是否值得信任。
:::

## 实战案例：虚构的独立书店，从市场里挑一个“口碑观察员” {#case}

一个虚构的场景（并非任何人的真实配置）：一家独立书店的店主，想知道网上有没有人提到自家书店，但不想自己每天去刷各个网站。

| 步骤 | 做法 | 注意点 |
| --- | --- | --- |
| 挑选 | 让主 Bot 在市场里对比两三个做“提及监测”的 Bot | 先只看对比，不导入 |
| 审查 | 读详情页：用哪些应用、有几个 Routine、会不会发帖 | 选了明确写着不替你发帖的那个 |
| 导入 | 选 Import Bot，回答它的开场问题：书店名、网址、店主笔名 | 不需要的数据源先不开 |
| 改造 | 让它记住：只在工作日早上汇报，没有新提及就不打扰 | Routine 跑通一次后才启用 |

### 亮点：先审后用，Routine 最后才打开 {#case-flow}

店主没有一导入就让它自动跑，而是先让它手动做一次，确认结果靠谱。

::: flow
- 我 | 说明想找什么样的 Bot | person
- 主 Bot | 在市场里挑候选并对比
- 口碑观察员 | 导入后提问并试跑一次
- 我 | 确认结果后启用 Routine | person
---
- 我 → 主 Bot：帮我在市场里找一个盯网上口碑的 Bot，先别导入
- 主 Bot → 我：找到三个，第二个只做汇总、不发帖，最符合你的要求
- 口碑观察员 → 我：试跑完成，找到两条新提及，都附了链接；每日 Routine 已建好但还没启用
- 我 → 口碑观察员：结果没问题，打开吧，周末不用发
:::

一个月后，店主又从市场导入了一个写替代文本的 Bot，给新书海报配上说明文字，做法完全一样：先读详情页，再试跑一次。

::: prompt
你是这个“口碑观察员”。以后请按下面规则：
1. 只汇报别人对 [书店名] 和 [网址] 的提及，自己发的不算；
2. 每条都附上原文链接和一句话概括；
3. 没有新提及的日子不要发消息，也不要替我回复或发帖。
先复述规则。
:::

## 社区玩法精选：市场里的几件作品 {#community}

本期从官方市场里挑了几个社区作者的作品，看看别人是怎么把“一件事”做好的。介绍都来自它们的详情页，使用前请自己再读一遍。

### dr eggbot：帮你设计 Bot 的 Bot {#c1}

作者 Lauren Tan。[dr eggbot](https://x.ai/bot/marketplace/bots/dr-eggbot-v2) 会先问你几个偏好问题，再按“一个 Bot 一件事、写明不做什么”的思路帮你建好 Bot。不知道怎么拆分工作时，可以从它开始。

### Tradbot：家里的事不漏掉 {#c2}

作者 Claire Vo。[Tradbot](https://x.ai/bot/marketplace/bots/tradbot-2) 盯着你的个人邮箱和日历，提醒学校表格、账单和活动回复，起草回复，但不会替你发送。

### Meeting Recap Deck：会议笔记变回顾幻灯片 {#c3}

作者 Krista Letz。[Meeting Recap Deck](https://x.ai/bot/marketplace/bots/echo) 按你的幻灯片模板，把会议笔记做成回顾演示稿，明确写着不会编造引语。

### Haggle Bot：找出该省的订阅费 {#c4}

作者 Daniel Gartshein。[Haggle Bot](https://x.ai/bot/marketplace/bots/haggle-bot) 盘点你的软件订阅支出，找出闲置席位、重复订阅和更便宜的替代，起草给供应商的还价邮件等你审核，不会替你花钱、签约或发送。

### Imogen：给图片写替代文本 {#c5}

作者 Kent C. Dodds。[Imogen](https://x.ai/bot/marketplace/bots/imogen) 为图片写简短、可复制的替代文本，抓住图里最重要的部分，方便视障读者理解。

## 本期小练习 {#exercise}

花 15 分钟，从市场里挑一个 Bot 试用。

::: steps
- 逛一遍市场 | 打开 Bot 市场，在和你工作最相关的分类里挑一个 Bot。
- 读详情页 | 用技巧二的提示词，让主 Bot 帮你检查它的应用、Routine 和会不会自动发送。
- 导入并提问 | 导入后用技巧三的提示词，让它先说清职责和 Routine，不要马上运行。
- 试跑一次 | 手动让它做一次，满意了再决定要不要启用 Routine。
:::
