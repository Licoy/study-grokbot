## 本期导读 {#intro}

[第 4 期](/zh/issues/2026-11-04/)讲过云端电脑和连接应用：Gmail、Notion、Slack 这类服务在目录里点一下就能连上。可总会遇到目录里没有的服务，比如团队自己用的小众工具、某个只提供 API 的数据平台。

官方给的办法有三层：先找现成应用；找不到就接入这个服务的 MCP 服务器；连 MCP 服务器都没有，就请 tinkabot 从 API 做一个插件。本期把这三层拆成 5 条技巧，再讲清密钥、权限和团队策略这些容易踩坑的地方。

::: callout 一句话记住本期
先查目录，再接 MCP，最后才自己做插件；密钥只走安全卡片，写入类操作加“先问我”的规则。
:::

## 可直接上手的 5 条技巧 {#tips}

每条技巧都附了一段示例提示词，把方括号里的内容换成你自己的，就能直接用。涉及登录和授权的步骤，要由你本人在浏览器里完成。

### 技巧一：先找现成应用，别急着自己接 {#tip1}

官方文档说，应用让 Bot 以结构化的方式使用服务，只要有现成应用，就比在网页上点来点去更可靠。动手接自定义工具之前，先确认目录里确实没有：

::: steps
- 打开目录 | 从侧边栏打开 Connect apps，搜索要用的服务并添加。
- 完成登录 | 提示 Authorize 或 Authenticate 时，在浏览器里完成服务商的登录。
- 确认已安装 | 在 Installed 里能看到它，才算装好。
- 挂到任务上 | 在对话里输入 @，把这个应用挂到当前任务上。
:::

也可以直接让 Bot 帮你装，比如说“添加 Linear 应用”。它会在目录里搜索并安装，需要你登录时会弹出 Connect 卡片；从你的下一条消息开始，这个应用的工具就能用了。

::: prompt
我经常要用 [服务名称] 处理 [具体工作]。
请先在应用目录里帮我找有没有这个服务的应用：
1. 有的话，告诉我它能做什么，再帮我添加，需要登录时给我 Connect 卡片；
2. 没有的话，告诉我这个服务有没有公开的 MCP 服务器或 API。
先不要用浏览器替我登录任何网站。
:::

### 技巧二：让 Bot 帮你接入 MCP 服务器 {#tip2}

目录里没有，但服务提供了 MCP 服务器时，可以直接交给 Bot。官方文档说明，Bot 可以用两种方式接入目录之外的 MCP 服务器：

::: props
- 按 URL 接入: 服务商给了远程服务器地址时，把地址告诉 Bot 即可
- 按命令接入: 用一条在 Bot 电脑上运行的命令启动服务器；这样启动的服务器，你的其他 Bot 也能用
- 需要批准的情况: 服务器在私有网络上，或者使用私有证书颁发机构时，Bot 会先请你批准
:::

::: prompt
请帮我接入 [服务名称] 的 MCP 服务器。
服务商文档里给的接入方式是：[粘贴服务器地址，或启动命令]。
接入前先告诉我：
1. 它会提供哪些工具，哪些是只读的、哪些会修改数据；
2. 需不需要我登录或提供密钥；
3. 接入后我的其他 Bot 能不能用到它。
等我确认后再接入。
:::

### 技巧三：在桌面端自己添加自定义连接器 {#tip3}

想自己动手，就在桌面应用里打开 Connect apps，拉到最底部，选 Add a custom connector，先填 Name，再选类型：

::: props
- Remote HTTPS: 填 Server URL；HTTP headers 和 OAuth Client ID 可选
- Command: 填 Command 和 Arguments
:::

填了 Client ID 之后，会多出一个 Client Secret 输入框。都填好后点 Add plugin 保存。如果团队管理员的 MCP 策略拦截了这个服务器，就保存不了。

注意，你自己添加的自定义连接器没有分享链接。想让同事也用上，把服务商的接入说明发给他，让他自己添加。

::: prompt
我准备在桌面端用 Add a custom connector 添加 [服务名称]。
下面是服务商的接入文档：[粘贴文档内容]
请帮我整理：
1. 应该选 Remote HTTPS 还是 Command；
2. 每个输入框分别填什么（密钥部分只写“由我自己填写”，不要写出具体值）；
3. 添加完以后，我该怎么确认它已经连上。
:::

### 技巧四：没有 MCP？让 tinkabot 从 API 做一个插件 {#tip4}

很多服务只有 API，没有 MCP 服务器。官方文档推荐的做法是用市场里的 tinkabot：它会把 API 包装成一个插件，里面有 MCP 服务器和技能，先测试，只有你明确同意才发布。

根据它在 Bot 市场里的介绍，发布前它只会问一次你是否就职于这家公司或服务商：是的话发布到 Cursor Marketplace，否则发布到 cursor.directory。它的介绍里还写明，Grok Bot 只从 Cursor 后台和市场加载插件。发布意味着公开上架，涉及公司内部系统的接口，先和团队确认是否适合公开。

从市场导入 Bot 的方法见[第 19 期](/zh/issues/2026-11-19/)。

::: prompt
@tinkabot 我想把 [服务名称] 的 API 包装成插件。
API 文档在这里：[粘贴链接或内容]。
我最常用的操作是：[列出两三个操作]。
请先说明你打算提供哪些工具、需要哪些密钥，测试通过后把结果告诉我。
没有我明确同意，不要发布到任何地方。
:::

### 技巧五：管好密钥和权限 {#tip5}

自定义工具一样要讲安全。官方文档里这几条最要紧：

::: steps
- 密钥不进聊天 | 任务需要 API 密钥时，Bot 会发给你一张安全密钥卡片，密钥一直是隐藏的，不会出现在聊天里。
- 令牌不给 Bot | 应用的登录令牌保存在 Cursor 的连接器后端，Bot 调用工具时拿不到。
- 权限不会变大 | 应用只能做你授权的那个账号本来就能做的事。
- 所有 Bot 共用 | 接入的应用对你所有的 Bot 都可用；同事的团队 Bot 用你的账号之前会先问你。
- 写入先问 | Bot 用应用之前会经过自动审查。可以在 Settings → General 的 Bot 下打开 Custom Rules，给“删除”“发布”这类操作加 Ask first 规则。
:::

审批与自定义规则的细节见[第 5 期](/zh/issues/2026-11-05/)，Vault 和安全密钥见[第 15 期](/zh/issues/2026-11-15/)。

::: prompt
我刚接入了 [服务名称] 的自定义连接器。
请帮我列出它的工具里哪些会修改、删除或对外发布数据，
并替我起草几条 Ask first 规则的描述（用一句话描述一类操作）。
只给草稿，我自己去 Custom Rules 里添加。
:::

## 接不上？先看状态 {#troubleshoot}

官方文档提醒，Added 只表示已经安装，不表示已经登录。在 Connect apps 里看它的状态：

| 状态或提示 | 怎么处理 |
| --- | --- |
| Needs auth 或 Disconnected | 点 Authenticate，完成登录 |
| Finish setting up | 先补上服务器地址等设置，再连接 |
| Disabled by team admin | 请团队管理员开启 |
| Connected 但还是不行 | 给 Bot 发一条新消息，请它再试 |
| Client Secret 一直被拒 | 先在连接器设置里更新 Client Secret，再重新连接 |

还不行，或者在服务商那边撤销过授权，就选 Remove，重新添加并登录。注意移除应用时，它带来的东西都会一起移除，你也会被登出。排障的一般顺序见[第 16 期](/zh/issues/2026-11-16/)。

::: prompt
我接入的 [服务名称] 用不了，Connect apps 里显示的状态是：[状态原文]。
Bot 给出的提示是：[粘贴提示原文]。
请根据官方文档告诉我下一步点哪里，需要找团队管理员的话帮我写清楚要他做什么。只给步骤。
:::

## 团队里用，要知道这些边界 {#limits}

::: steps
- 继承连接器策略 | Grok Bot 沿用团队在 Cursor 里的连接器策略，没有单独的 Grok Bot 连接器列表；被拦截的显示 Disabled by team admin。
- 允许清单是企业版功能 | MCP 允许清单只在 Enterprise 方案里有，在后台的 Plugins & MCPs 页面设置。
- 网络策略默认不管 MCP | 团队用了允许清单式的网络策略，还要打开 Apply to MCP servers，远程 MCP 服务器才会受同一份清单约束；这个开关默认关闭。
- 命令型服务器另算 | 在电脑上用命令运行的服务器本来就受网络策略约束，不受这个开关影响。
- 不能强推连接器 | 管理员不能把连接器强制或默认推给成员，成员要自己在 Connect apps 里添加。
:::

## 实战案例：虚构的五人设计工作室，接入一个小众看板工具 {#case}

一个虚构的场景（并非任何人的真实配置）：一家五人设计工作室用一款小众看板工具管理项目，目录里没有它的应用，但服务商提供了远程 MCP 服务器和 OAuth 登录。

| 步骤 | 做法 |
| --- | --- |
| 查目录 | 让主 Bot 在目录里搜，确认没有 |
| 读文档 | 把服务商的接入文档交给主 Bot，整理要填的内容 |
| 添加 | 自己用 Add a custom connector 选 Remote HTTPS 添加 |
| 登录 | 点 Authenticate，在浏览器里登录看板账号 |
| 加规则 | 给“删除看板卡片”加一条 Ask first 规则 |

### 亮点：Bot 整理、人来授权 {#case-flow}

整个过程里，Bot 只负责读文档、列清单和事后检查；填密钥、登录授权都由负责人自己完成。

::: flow
- 负责人 | 提出需求，自己添加连接器 | person
- 主 Bot | 查目录、整理填写清单
- 看板工具 | 通过 MCP 提供工具
---
- 负责人 → 主 Bot：我们的看板工具目录里有吗？没有的话帮我看看这份接入文档
- 主 Bot → 负责人：目录里没有。建议选 Remote HTTPS，地址和 Client ID 我列好了，Client Secret 请你自己填
- 负责人 → 主 Bot：已经添加并登录好了，帮我列出本周到期的卡片，只读，不要改动
- 主 Bot → 负责人：这是本周到期的卡片清单；里面有删除卡片的工具，建议加一条 Ask first 规则
:::

::: prompt
从今天起，处理 [看板工具名称] 时请遵守：
1. 默认只读，需要新建、修改或删除卡片时先列出改动等我确认；
2. 不要把看板里的客户信息转发到其他应用；
3. 连接断开时提醒我重新登录，不要改用浏览器登录。
先复述规则。
:::

## 社区玩法精选：用好自定义工具 {#community}

本期整理了几种接入自定义工具的做法：前三条出自官方文档的最佳实践，后两条是基于官方文档的延伸用法，供你参考。

### 常用服务都连上 {#c1}

官方建议：经常用的服务都连一个应用；没有应用就加它的 MCP 服务器，或者让 tinkabot 从 API 做一个。比起让 Bot 每次打开网页操作，这样更稳定。

### 密钥一律走安全通道 {#c2}

官方建议永远不要把密钥贴进聊天：密码走 Vault、1Password 或安全表单，API 密钥走安全密钥卡片。

### 先跑通，再沉淀成技能 {#c3}

官方建议先把一个任务跑通一次，再保存成技能，然后用 Routine 定时或按事件运行。新接入的工具也一样，先手动用几次，再交给 Routine。

### 先只读，后写入 {#c4}

新工具刚接上时，先让 Bot 只做查询类操作，确认返回的数据没问题，再逐步放开写入，并给删除、发布这类操作加 Ask first 规则。

### 写编程活交给 Cloud Agents {#c5}

如果某个工具还要写代码改造，官方文档说明 Bot 可以把编程任务交给 Cursor Cloud Agents，完成后把报告里的图片、视频等文件附在回复里；团队管理员可以关闭这项委派。
